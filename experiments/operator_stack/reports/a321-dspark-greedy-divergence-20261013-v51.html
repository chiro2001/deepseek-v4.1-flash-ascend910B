DSpark 贪心路径 vs 1 行 decode 的 gsm8k-12 分叉：完整归因（2026-10-13 v51）

结论先行：分叉由"量化网格上的近并列步"造成，不是 accept/rollback 语义错误。 DSpark 侧的逐轮收据显示每一步的发出 token 都是其自身上报分布的 top-1， 接受的 draft 等于 verifier 的 argmax；分叉点是 verifier 的 bonus token（第 19 个答案 token）， 该步 DSpark 上报分布 top-1/top-2 精确并列，而 A1（1 行 decode）在同一上下文里 top-1 领先 0.25。

单 prompt 同步 DSpark 诊断（formal_dspark_gsmdiag_v1，64 token、K=5、draft-graph、 逐轮收据 + top-8 logprobs）：

  • 前 18 个答案 token 与 A1 逐位一致；
  • 第 19 个 token：DSpark 发出 671("The")，A1 发出 58559("Carl")；
  • 该 token 是第 5 轮的 bonus token（verifier 自己的 argmax；轮次流相对输出流少第一个 prefill 后 token，属于既有边界约定）。

同一步上报分布（top-2）：

  • 两条路径的 top-k logprob 差都落在同一量化网格上（0.125 的整数倍，含共同偏移）， 即该 stack 的 logits/logprob 以约 1/8 步长呈现（与 W4A8/qrot 量化输出一致）；
  • DSpark 侧顶部两 token 恰好同为 0 步 → 以最低索引 671 打破并列； A1 侧 "Carl" 领先 2 步 → 选 "Carl"。后续推理走向不同结论（12 vs 13）。

3. accept/rollback 语义核查（诊断收据）

  • 第 i 步发出 token 均为其 logprobs[i] 的 top-1（对 i=16..25 全查，且整流如此）；
  • 逐轮：scheduled_draft_token_ids 与 accepted_draft_tokens_raw 一致地解释每个发出 token （accepted 位置= draft 值；bonus 位置=回退采样值）；
  • 轮次流与输出流的唯一差异是首个生成 token 不在轮内（prefill seed 边界），与既有约定一致；
  • 未发现"接受未验证 draft"或"跳过位置"的迹象。

⇒ 这是数值层问题：两条计算路径（1 行 decode vs 6 行 verify）在同一量化网格上 给出至多一步（0.125）的差别，恰好在该题把并列从"2 步"变成"0 步"。
