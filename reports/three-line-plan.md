### 线 3 的边界：单算子 vs 单层（回答用户的"或者单层？"）

| 粒度 | 可行性 | 结论 |
|---|---|---|
| **单算子** | ✅ **已证明**：`bash run.sh 50` 全流程 41 s，一轮改动 20–30 s | **主力形态** |
| **单层（MoE 段）** | ✅ 可行 —— gate + shared expert + routed experts 是干净的自包含单元 | 推荐做 |
| **单层（attention 段）** | ⚠️ 勉强 —— 需要 KV cache + 复杂 metadata（`sas_metadata`/`qli_metadata`/block_table），且**删掉通信后语义就变了** | 只做算子级，不做"整层" |
| **整层（含通信）** | ❌ 单卡做不到（TP8 的层被切成 1/8，allreduce/allgather 不存在） | 交给线 2 的 8 卡 dummy |

**一句话**：**单算子为主 + MoE 段单层为辅**；attention 与通信相关的判定一律回 8 卡（线 2）。

## 3.5 ⚠️ 两条来自线 3 的重要更正（**改变收益模型**）

### 更正 1：「5 µs/算子下发空隙」对**图内**算子不成立

线 3 用真实 profile 量了 **stream 140 同流相邻 kernel 的间隙**：

```
中位数 = 0.00 µs ／ 均值 = 0.04 µs ／ n = 11013
```

⇒ **图内算子之间几乎零下发空隙**（aclgraph 重放），
**审计报告里"每减少 1 个算子省 5 µs"的记账模型是错的**。
图内必须按**纯设备时间**记账。

**影响**：`small-op-audit.md` 的 Top-5 收益（≈2.34 ms）需要按新模型重估。
好处是**削减算子本身仍然有价值**（因为算子自己的 device 时间是真实的），
只是不能再用"下发空隙"去外推。

### 更正 2：审计候选 1「直接删掉 MoE 掩码」是**错的**（会造成正确性事故）

线 3 实测：删掉掩码后输出被污染（`max_abs=nan`、cannbot BF16 判据 `fail=640/40960`）。

**机制**：`expanded_row_idx` 对非本 rank 的 `(token, k)` 填 **−1**，
而 `npu_moe_token_unpermute` 会把这些**从未写入**的 `permuted_tokens` 行
乘上权重 —— 掩码置 0 正是用来压掉它们。**不能删。**

**正确的替代**（线 3 已实现）：连续区间映射下
`expert_map[topk_ids] != -1` ≡ `(topk_ids >= first) & (topk_ids < last)`，
用 int32 范围比较 + `masked_fill` 替换 `Index+IndexCheck`。

实测（8 卡 rank0 op_summary，74 步 × 40 层）：

| 子算子 | µs/层 |
|---|---|
| `Index` | 4.889 |
| **`IndexCheck`** | **9.545** |
| `NeScalar` | 1.27 |
| `Mul` + `Cast` | 2.46 |
| **合计** | **18.16 µs/层 = 0.726 ms/步** |

新实现单卡 7.72 µs/层 ⇒ **投影 −0.40 ms/步**。
门控 `V41_MOE_MASK_RANGE=1`，数值**逐位相同**（`max_abs=0.000e+00`）。
交付：`~/handoff/patches/moe-mask-range/`（已在 A3-node1 应用并进入验证）。

### 更正 3：dummy 墙钟分不出 <1 ms 的改动（详见 `dummy-line-protocol.md`）

用已知答案（F3 = −0.3~−0.8 ms）校准 dummy 墙钟：**会话间方差 1.5–2 ms**，
远大于效应量 ⇒ **dummy 线必须用 device 账目，不能用墙钟**。

### 为什么两条线都不能省（数据说话）

当前 128K：`A=3.493` 时 `ms/step=32.894` ⇒ **106.6 tok/s**。
要 110 tok/s（A=3.493）需 **ms/step ≤ 31.75** ⇒ **只差 1.14 ms**。

而 `small-op-audit.md` 的 Top-5 算子削减合计 **≈2.34 ms** ⇒
**线 3 的产出（若兑现一半）就能跨过 110 的门槛**。
⇒ 线 2 的价值就是把线 3 的产出**在 8 卡上快速确认**（否则每次都要付真权重的起服代价）。

## 2. 流水线（关键：谁交给谁）

```
线3 单卡（20–40s/轮）──patch+数值等价──▶ 线2 dummy（~5min/起服）──8卡时延──▶ 线1 真权重（~7min）
                                               │                                │
                                               └──── 若时延有收益 ────▶ 精度门 + 非确定性诊断
                                                                                │
                                                              通过 ──▶ 采纳 / 进交付包
```

**规则**：
1. 线 3 **不判** 8 卡收益（单卡/8卡比值散布 0.71×–1.41×）；
2. 线 2 **不判** 精度、**不判** 接受率（dummy 下 A 恒为 1.0）；
3. 线 1 **不判** 时延优劣（只有一个 8 卡实例，起服贵）；
4. 任何改动**上生产配置前必须过线 1 的精度门**。
