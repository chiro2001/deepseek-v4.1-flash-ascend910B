# 刀锋实验（a3-22 tiny 1+1）证据 2026-09-25

## 这是什么

在 a3-22 的 **1+1（P=chip0 / D=chip1，tiny dummy 权重）**上，用"新鲜池 + 同长度大请求
序列"把 D 侧 g0 的**最大物理块号精确钉在指定值**，逐点检验"失败 ⟺ 块号 ≥ 某个固定
常数 B"这条假说。

落点方法（本实验建立，精度实测 0 误差）：
- 单请求自己的 g0 块数 `c(n) = ceil((n-1)/128)`（18/18 点吻合）
- 新鲜池 + 同长度大请求：`min(k) = 1 + k(c+21)`、`max(k) = c + k(c+21)`
  （`+21` 是其它组的固定额外块；实测连续 50 步逐条精确）
- 要"某条请求恰好停在池顶 top"，只需求解 `c + k(c+21) = top` 的 (c,k)

## 1M 级复现（BIGM2 臂，最关键）

前提：tiny 的 `MAX_LEN` 可开到 **1048576**（config `rope_scaling: yarn, factor=16`，
65536×16），仅 4 条无害告警 `Unrecognized keys in rope_parameters`。

| # | prompt | c | g0 min..max | 判决 | 首token / logprob |
|---|---|---|---|---|---|
| 1 | 1019522 | 7966 | 1..7966 | PASS | ' SJ' / -11.769637 |
| 2 | 1019522 | 7966 | 7988..15953 | PASS | ' SJ' / -11.769637 |
| 3 | 1019522 | 7966 | 15975..23940 | PASS | ' SJ' / -11.769637 |
| 4 | 661250 | 5167 | 23962..**29128** | PASS | ' SJ' / -11.769637 |
| 5 | 661250 | 5167 | 2779..7945（绕回，低块号对照） | PASS | ' SJ' / -11.769637 |

第 4 条与 a3-21 真权重失败点（C=29129、max=29128、c≈5183）几乎同形，**tiny 仍通过**。

## 判读

- tiny 1+1 **无法复现**该失效模式：C=29600 时 max=29599 仍 PASS，C=29129 时 max=29128 PASS；
  而 8+8 真权重在同一 max 下必失败（同实例细扫 29063 PASS / 29084 FAIL）。
- 该故障**不是纯 KV 几何/块号问题**，需要真权重或 8+8 拓扑才能复现。

## KV 几何（tiny 与真权重逐字节一致）

```
num_blocks=C  n_addr=4  block_len=[131072,131072,131072,147712]  block_stride=[同]
swa_cache layer0      stride=(65536,512,512,1) bf16   block_stride_bytes=131072
swa_cache layer3/20   stride=(73856,512,512,1) bf16   block_stride_bytes=147712
long_kv_cache layer20 stride=(73856,512,512,1) bf16   block_stride_bytes=147712
indexer.k_cache l20   stride=(147712,128,128,1) int8 block_stride_bytes=147712
```
合计 **540928 B/全局块号**（3×131072 + 147712）。

## 环境坑（复现时注意）

- a3-22 的 `/home`（ext4，`stripe=32`）在**主机负载 ~45-50** 时会出现**瞬时路径查找
  失败**（宿主侧对刚写入的文件 `No such file or directory`，容器内正常）。本次实验因此
  改用两种绕法：工具链放 `/tmp`（tmpfs）、dump 走 `docker exec` 读容器视图。
- 每次换臂必须 `docker rm -f` 旧 D 并确认 `18961` 返回非 200，否则旧容器会替新容器答 health。
