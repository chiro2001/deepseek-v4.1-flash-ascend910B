# 短切片专用问题（1024 token 口径）

`data/hlm/suffix_*.txt` 那四个后缀是**为全本设计的**（"引第五回原文"、"三人的感情走向"、
"贾府兴衰"、"全书词频 Top10"）。把它们配到 1024 token 的正文切片上，**四分之三的问题
在给定上下文里无解** —— 模型只能编或回避，输出分布偏移，投机解码接受长度会明显下降
（实测：合成 filler + 概括任务 = 3.34，全本问题配 1024 切片 = 2.21）。

因此短切片口径单独用这四个后缀：**每个都只依赖切片内部信息**，任务类型尽量分散。

| 文件 | 任务类型 | 是否只依赖切片 |
|---|---|---|
| `local_quote.txt` | 逐字摘录 | ✅ 摘本段内的句子 |
| `local_qa.txt` | 抽取式问答 | ✅ 问本段出现的人物/情节 |
| `local_continue.txt` | 续写 | ✅ 接着本段写 |
| `local_extract.txt` | 词频统计 + 定位 | ✅ 统计本段用词 |

四个任务轮换 ⇒ 每个请求的"输出分布"不同，避免单任务偏好把曲线拉平。
