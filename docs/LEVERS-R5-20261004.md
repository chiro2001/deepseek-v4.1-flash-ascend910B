## 3. 一个测量口径的澄清（影响报数）

`bench_concurrency` 的 **N=1 tok/s 是各 prompt 接受长度 A 的调和平均 ÷ 步长**，
因为 `conc=1` 会把全部 16 条 prompt 依次跑完，而 `total_decode = Σn_out / Σwindow`、`window ∝ 1/A`。
单 prompt 直测（A=3.267、步长 25.50ms）给 **123.7 tok/s**，而 bench 报 **107.6**（A=3.48）—— 差 15%。
⇒ **不是服务问题**，但报数必须注明 A 分布；同一 prompt 集内的 A/B 对比仍然有效。
