# ★ 贪心输出的**批大小依赖**：同 prompt 在 N=1 与 N=8 下生成不同文本（2026-10-05）

> 起因：`bench_concurrency` 的接受长度 A 在 N=1 是 2.87、N=8 只有 2.52（−12%），
> 而两档用的是**同一批 prompt**、`temperature=0.0`、`ignore_eos=True`。
> 直觉会判成"draft 在多请求下变差"⇒ 一个可修的性能 bug（值 ~10% 吞吐）。
> 本文用三个实验判定它，结论**不是**可修 bug。
> 标注：【实测】。

## 1. 三个实验

### 实验 1：同批 prompt，只改并发（对拍 /metrics 差分）
8 条同后缀 prompt：串行 A=**1.759** → 并发 A=**1.725**（**−2.0%**）。

### 实验 2：换成 bench 真正用的 4 种后缀（continue/extract/qa/quote），16 条
| | 串行 N=1 | 并发 N=16 | 相对 |
|---|---:|---:|---:|
| **A（平均接受长度）** | **2.790** | **2.618** | **−6.2%** |
| 接受率 | 35.8% | 32.4% | −9.6% |
| 位置 0 接受率 | 0.709 | 0.665 | −6.2% |
| 位置 1 | 0.442 | 0.401 | −9.3% |
| 位置 2 | 0.284 | 0.252 | −11.3% |
| 位置 3 | 0.202 | 0.174 | −13.9% |
| 位置 4 | 0.154 | 0.127 | −17.5% |

⇒ **复现了**（与 bench 的 −12% 同量级），且**从位置 0 就开始掉** ⇒ 不是"后段 KV 串了"。

### 实验 3（决定性）：同一批 prompt，比较**生成文本**
8 条 prompt，N=1 串行跑一遍、N=8 并发跑一遍，逐条比对输出：

| prompt | 结果 |
|---:|---|
| 0 | **不同**，首个差异在第 19 个字符 |
| 1 | **不同**，第 0 个字符 |
| 2 | **不同**，第 46 个字符 |
| 3 | **不同**，第 21 个字符 |
| 4 | **不同**，第 4 个字符 |
| 5 | **不同**，第 25 个字符 |
| 6 | **不同**，第 120 个字符 |
| 7 | 完全相同 |

**⇒ 7/8 条的生成文本就不同了。**

## 2. 结论

* **A 的下降是"文本变了"的副产品，不是 draft 变差**。贪心解码下，只要批大小改变，
  矩阵乘的累加顺序/分块就会变化 ⇒ logits 有极小差异 ⇒ 偶尔翻转 argmax ⇒ 输出轨迹分叉。
  分叉之后，"文本好不好预测"变了，接受长度自然变。
* 因此 **不存在"把多请求下的 draft 修好"这种改法**；要提升 N=8 的 A，
  等价于要求**批不变（batch-invariant）的前向**，那是另一类工程（固定分块 + 固定归约顺序）。
* 这也解释了一条历史观察（用户曾报"多流下推测解码性能掉得很快"）：**掉的一部分是文本驱动的**，
  不全是 batching 变慢。

## 3. 对交付的三条影响（都要写进口径纪律）

1. **跨并发档的 `A` 不可直接比较**。`bench_concurrency` 各档的 A 差异里，
   既有"批效率"也有"文本不同"；报数时必须同时给出 A，且**不把 A 的变化当成纯性能信号**。
2. **同并发档的 A/B 仍然有效**（两臂面对同一种批行为，差别来自被测改动）。
   但要注意：如果改动改变了输出轨迹（例如修了某个数值 bug），A 会跳变，
   这时**不能把它当成性能收益**，要单独说明。
3. **可复现性**：同一个 prompt 在不同并发下输出不同 ⇒ 任何"同 prompt 逐字节对拍"的
   正确性判据**必须在同并发下做**（我们已有的 144K 四针、并发 2 不同针等用例都满足）。

## 4. 待评估（**不建议现在做**）

* 若要真正的确定性，需要 batch-invariant 的算子实现（固定 tiling + 固定归约树），
  代价是放弃现有的形状自适应 tiling，**很可能净亏性能**。
* 一个更便宜的方向：把 `ignore_eos` 的压测改成**固定 token 数 + 无采样**，
  并在报告里同时给出"该档实际 A"与"按统一 A 归一化的 ms/step"，
  这样跨档比较就不受文本影响了（`tools/bench_delta.py` 已按 `ms/step = 1000·A/单流吞吐` 给数）。

## 5. 复现
