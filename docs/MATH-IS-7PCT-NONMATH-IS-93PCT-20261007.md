# ★ 决定性量化：单流步长里**真数学只占 7.4%**，其余 92.6% 是标量寻址/搬运/同步

> 方法：用 profile 的 **per-op 子计数**（`aic_mac_time` / `aiv_vec_time` / `*_scalar_time` /
> `*_mte*_time`）逐算子归因，比"形状估字节"可靠得多。
> ⚠️ 为什么不用形状法：稀疏注意力/分页 KV/MoE 分片的 `Input Shapes` 是**整块缓存或整份权重**
> ——实测形状法把 `SparseFlashMla` 的 1.7 GB indexer cache 整块算进去，**高估 200×**（作废）。
> 数据：纯 conc=1 新 profile（tp8k5，步锚 `HcPre/86`，1854 步，步长 25.458 ms，2821 算子/步）。
> 全部为【实测】。

## 3. ★ 第二个决定性发现：**搬运本身也远未达峰**

每步必须搬的字节（`A3-DECODE-BANDWIDTH-AND-CACHE` 解析式，已验证与 `npu-smi` 吻合）：**≈4.2 GB**

| | 值 |
|---|---:|
| Σ 搬运时间（MTE） | **10.382 ms** |
| 反推有效带宽 | **4.2 GB / 10.382 ms ≈ 405 GB/s** |
| 峰值（纯读） | **1300 GB/s** |
| **利用率** | **31%** |

**但要注意其中有一部分已在峰值**：MoE 两个 GEMM（3.1 GB）实测跑在 **845 GB/s（~峰值）** ⇒
那 ~3.7 ms 是"该花的"。**剩下 ~6.7 ms 的 MTE 只搬了 ~1.1 GB ⇒ 164 GB/s（13% 峰值）。**

⇒ **小算子的搬运效率只有峰值的 13%**（每个算子只搬几百 KB，tiling 吃不满带宽）。

## 4. 这对"下一步该做什么"意味着什么

### 4.1 为什么"改一个算子/融两个算子"都不会有感觉

* `hc_pre_norm` 把 2 个算子融成 1 个：省 **0.115 ms（0.46%）** —— **低于判据下限（1%）**，
  所以 E2E 测不出（见 `AB-PRECISION-FLOOR`）；
* 单算子限核：**核数不是成本驱动项**（见 `HCPRE-LIMITCORE-NEGATIVE`）；
* ⇒ **因为 92.6% 的时间不是"某个算子慢"，而是"2821 个算子各自的开销叠加"。**

### 4.2 唯一可能拿到两位数的路：**多合 1 的深度融合**

**理论空间**（本次实测给出）：

```
真数学                              1.871 ms   ← 不可再减（是模型本身）
MoE 的带宽搬运（已在峰值）            ~3.7 ms   ← 不可再减
其余全部（标量 + 低效搬运 + 同步）  25.458 − 1.871 − 3.7 ≈ 19.9 ms   ← 可动
```

**保守估计**：若深度融合能把"标量 + 同步"砍掉一半、把低效搬运提到峰值一半：

```
可省 ≈ (8.03 + 9.54)/2 + (6.7 − 3.35) ≈ 8.8 + 3.35 ≈ 12 ms  ← 上界（不现实）
更保守：只砍 1/3 的标量与 1/3 的同步 + 搬运提效 2×：
可省 ≈ 5.9 + 3.35 ≈ 9 ms  →  25.5 → 16.5 ms（1.55×）
```

**即使只兑现 1/5**（真实工程常见折扣）：**可省 ~2.4 ms = 步长 −9.4%**，
**已经接近本目标的 −12%**；兑现 1/3 则 **超过目标**。

### 4.3 与"多合 1"该选哪些

按"非数学毫秒 × 可融合性"排序（从 §2 与融合族分析交叉）：

| 目标 | 非数学 ms | 融合思路 |
|---|---:|---|
| **`HcPre`（86 次）** | **2.703** | 与 `RmsNorm`/`quant`/`RoPE` 合成"层前处理"一个 kernel |
| **注意力矩阵乘族（`QuantMatmulV3` 226 + `MatMulV2` 111 + `MatMulV3` 49）** | **4.97** | 把 **`wo_a`+`wo_b`（80 次）** 与小投影合并 / 减少中间张量 |
| **MoE 前处理（`MoeInitRouting` + gating + unpermute，129 次）** | ~1.4 | gating+routing 合 1；routing 的输出直接喂 experts（省一次往返） |
| **norm/quant/RoPE 族（F3+F7，567 次）** | ~1.5 | 合成 1 个"norm→quant→RoPE→scatter" |
| **位置/槽位链（F1，470 次）** | ~0.5 | 下沉为 1 个 kernel（已有 `_compute_slot_mapping_kernel` 先例） |

**建议的第一个"多合 1"目标**：**`HcPre` + `input_layernorm` + `quant`**（层前处理链），
它每层 3 个算子、43 层 ≈ **129 次调用**，非数学合计 **~3.2 ms**。
