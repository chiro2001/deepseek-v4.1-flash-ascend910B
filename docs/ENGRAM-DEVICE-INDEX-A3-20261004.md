# Engram 设备侧索引（`ENGRAM_DEVICE_INDEX=1`）：A3 单实例新默认 —— 步时 −2.5~3.8%（2026-10-04）

> 结论：把交付的 `ENGRAM_DEVICE_INDEX` 从 **0**（强制走 host lookup）改成 **1**（设备侧索引），
> 每 decode 步时间按 batch 全面下降 **2.5–3.8%**，容量与正确性不变。
> 已设为 **A3 单实例入口（`scripts/serve_a3.sh`）的默认**；CED-PD 保持 0（未验证）。

## 1. 为什么以前是 0（以及为什么现在要改）

`ENGRAM_DEVICE_INDEX=1` 用驱动的 `host_mem_pool` 把两张 engram 表（L1/L14，各约 3.84 亿行 × 256B）
**直接映射成设备可寻址**（`[DEVICE-INDEX] Engram 表已映射为设备可寻址：…（每张 256B/行，HBM 占用 0）`），
从而**整条替换** host lookup 路径（D2H → CPU gather → pack H2D → all_to_all → broadcast）。

交付配置里它是 `0`（= 强制关），而 `serve_a2.sh` 的默认是 `auto`
（A3 探测通过 ⇒ 开；A2 不通过 ⇒ 回退 host）。⇒ **A3 实例一直在走最贵的 host 路径**。

【实测·审计】`[bneck]` 同窗口读数：host 路径下 **`d2h` p50 = 10.10 ms / p90 = 23.12 ms**（n=3136）。

## 2. 受控 A/B（同机、同脚本、同参数、同一批 prompt）

|---:|---:|---:|---:|
| 6 | 26.15 ms | **25.34** | **−3.1%** |
| 12 | 29.24 | **28.17** | **−3.7%** |
| 18 | 32.92 | **31.68** | **−3.8%** |
| 24 | 33.73 | 33.02 | −2.1% |
| 30 | 39.33 | 36.45 | −7.3% |
| 42 | 41.91 | 40.65 | −3.0% |
| 48 | 42.60 | 41.54 | −2.5% |

（n>100 的是 prefill chunk，已排除。）

> ⚠️ **为什么用"步时"而不是 `tok/s` 作主判据**：投机解码的接受长度 `A` 在 run-to-run 间
> 摆动很大（历史同配置 2.79–3.63），而 `tok/s = A / 步时`。本轮 N=8 的 `tok/s` 反而
> −2.0%，但同批 `A` 从 3.61 掉到 3.21 —— 按步时归一后 N=8 实际是 **81.3 → 73.7 ms（−9%）**。
> ⇒ **报 `tok/s` 必须同时报 `A`**。

（审计一开始提示"不要按 38% 记账"，实测证实这条纪律是对的。）

## 4. 落地

* `scripts/serve_a3.sh`：新增 `export ENGRAM_DEVICE_INDEX=${ENGRAM_DEVICE_INDEX:-1}`（含本节依据）。
* `scripts/serve_a2.sh`：**保持 `auto`**（A2 目标机上 `host_mem_pool` 不可用，必须回退 host）。
* `deploy/a3-ced-pd/launch/_common.sh`：**显式 `0`，不动**（CED-PD 未验证该路径）。
* 回退：`ENGRAM_DEVICE_INDEX=0`。

## 5. 顺带的两个修复（同一轮）

* **探针 flag 误判**：`patches/files/engram_hbm.py` 的 `_RouteProbe.on` 原为
  `bool(os.environ.get(...))` ⇒ 值为 `"0"` 时字符串非空被当成 True，**探针被强制打开**
  （交付日志实测 1480–2760 行 `[route-probe]`）。已改为显式解析，本轮实测 **0 行**。
  同类写法另两处（`V41_ENGRAM_REUSE_EP_GROUP` / `V41_ENGRAM_HOST_RESIDENT`）交付值恰好是 `1`
  ⇒ 当前无害，但**设 0 关不掉**，已记为潜伏项。
* **OPP 覆盖安全闸**：启用 `V41_HC_OPP_PKG`（自定义 kernel）时把 ready 上限从 2100s 收到 600s
  并打印指向 kernel 的提示 —— 实测不兼容 kernel 会让服务"看着在启动"却永不 ready。
