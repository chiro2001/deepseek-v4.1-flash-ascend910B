# ★ 更正：抖动的**可见性取决于分布饱和程度**，且 tiny 对比被三重混淆（2026-10-07）

> 本轮用**受控隔离**（只改一个变量）把上一轮几处矛盾的数字对齐了，
> 并发现此前"tiny 确定 / tp8k5 不确定"的对比**不成立**。全部为【实测】。

## 0. 结论

| 项 | 结论 |
|---|---|
| **prefill 逐位确定** | ✅ 仍然成立（1240 位置 × 8 轮 max\|Δ\|=0.000） |
| **decode 抖动** | ✅ 存在，但**是否可见取决于输出分布是否饱和** |
| 决定可见性的**不是** `max_tokens` | ✅ 受控隔离证明：改 `max_tokens` 48→4 不改变性质 |
| 决定可见性的**是 prompt 内容** | ✅ 无后缀（续写、分布饱和）⇒ 波动 0.000；有后缀（问句、分布平）⇒ 波动 0.30~0.40 |
| **tiny 的"确定性"不可用** | ❌ tiny 跑 `--load-format dummy`（随机权重）⇒ 输出退化成重复 ⇒ **分布饱和 ⇒ 抖动被掩盖** |

## 1. 受控隔离（每次只改一个变量）

同机（tp8k5、交付配置、graph 模式）、同一批 10 轮：

| 测试 | prompt 后缀 | max_tokens | `prompt_logprobs[-1]` 波动 | **`logprobs[0]`（首生成）波动** |
|---|---|---:|---:|---:|
| A | 无 | 4 | 0.000e+00 | **0.000e+00** |
| B | 无 | 48 | 0.000e+00 | **0.000e+00** |
| C | 有（"请概括上文。"） | 4 | 0.000e+00 | **4.02e-01** |
| D | 有 | 48 | 0.000e+00 | **3.04~3.67e-01** |

（A/B 与 C/D 的差别只有**后缀**；A/C 与 B/D 的差别只有 `max_tokens`。）

⇒ **`max_tokens` 无关；`prompt` 的后缀（内容）决定抖动是否可见。**

### 1.1 为什么"内容"会决定可见性

| 情形 | 输出分布 | 后果 |
|---|---|---|
| 无后缀（模型在**续写**已有文本） | **极度饱和**（实测 `logprobs[0] = -0.000001`，即 p≈1） | 同样大小的 logits 相对扰动，几乎不改变 logprob ⇒ **观察为 0** |
| 有后缀（模型要**回答一个问题**） | 平坦（top-1 概率远低于 1） | 同样的相对扰动被放大约 6 个数量级 ⇒ **观察为 0.3~0.4，并可翻转 token** |

⇒ 这两组数据**并不矛盾**，它们测的是同一个底层扰动在不同分布下的**可观测性**。

## 2. tiny 对比为何不能用（三重混淆）

我之前写"tiny（TP=2）逐位 0 差 ⇒ 非确定性是 TP=8 特有"。实际上：

| 维度 | tp8k5 | tiny |
|---|---|---|
| TP | 8 | 2 |
| `dsa_v41.py` | **镜像烘焙版 1092 行** | **开发版 4636 行** |
| 权重 | **真实权重** | **`--load-format dummy`（随机权重）** |
| 输出 | 正常文本 | **退化成重复**（实测 `'的一个。的一个。…'`）⇒ **分布饱和** |

⇒ tiny 的"0.000"**极可能只是饱和掩盖**（与 §1 的 A/B 两行同因），
而**不能**作为"TP=2 无抖动"的证据。该对比**撤回**。

## 3. 目前**仍然成立**的结论（未被本轮推翻）

| 结论 | 依据 |
|---|---|
| **prefill 路径逐位确定** | 1240 位置 × 8 轮 max\|Δ\|=0；且与内容无关（T=32/1024/1240 三次） |
| **抖动在 decode 路径进入** | 同一响应内：prefill 末位稳定、首生成 token 开始波动（C/D 组） |
| **投机解码不是根因** | `SPEC=0` 判别重启：抖动同量级 |
| **scatter 算子不是根因** | 4 种用法 × 100 次逐位相同 |
| **小 T 的 TP allreduce 不是充分原因** | prefill 在 T=32 也逐位确定 |
| **图模式放大** | eager 下 token 身份 0 处不同；graph 下大量不同 |

## 4. 仍未确认（且现在知道需要更严格的设计）

1. **TP 规模 vs 代码版本**：目前**没有**一个干净的 A/B 能隔离这两者
   （需要 TP=8 但换代码，或 TP=2 但用真实权重 + 开发版代码）。
2. **可见性阈值**：抖动幅度与"分布平坦度"的定量关系未测（需要构造从饱和到平坦的连续谱）。
3. **是否影响准确率**：长文针门 **24/24 通过**，说明对"抽取/问答"类任务影响小；
   但**没有做过"同一问题多轮，答案正确率"的统计**。

## 5. 对验收门与交付的建议

1. **门①不能再用"逐位 max\|Δ\|=0"**（当前交付件在平坦分布下必然不满足）。
   建议改为**按内容分级**：
   * **高置信/抽取类**（分布饱和）：要求逐位一致 —— 当前实测**满足**；
   * **开放生成类**：只要求"多轮答案**语义/正确率**一致"，不要求逐位。
2. **报告任何精度数字时必须写明任务类型**，否则"是否确定"这个结论会随内容翻转。
3. **性能结论不受影响**（`ms/step`、吞吐都是统计量；`MAX_SEQS=64` 的 +32~37% 仍成立）。
