# 吞吐测试方法论：为什么"单流 tok/s"必须配上下文看

> 2026-09-17 实测（A3，8×910C，TP8+EP8，`MAX_SEQS=64 PREFIX=1`，prompt 精确 1024 token，输出 256 token）。

## 1. 核心发现：tok/s 被文本退化严重污染

同样的服务、同样的长度口径，**只换 prompt 内容**，单流吞吐可以在 **45 与 145 tok/s** 之间摆动（3.2×）。
机制是投机解码的接受长度，而接受长度又由**输出文本的可预测性**决定：

| 任务 | tok/s | 接受长度 | 接受率 | 输出性质 |
|---|---:|---:|---:|---|
| 《红楼梦》续写 | **45.0** | 1.43 | 8.7% | 真实续写文言文（高熵） |
| 《红楼梦》引原文 | **50.5** | 1.58 | 11.7% | 真实作答 |
| 《红楼梦》分点问答 | **85.2** | 2.77 | 35.4% | 结构化输出 |
| 《红楼梦》词频统计 | **90.4** | 2.97 | 39.3% | 结构化列表 |
| 《红楼梦》词频统计（本地） | **101.9** | 3.56 | 51.2% | 结构化列表 |
| 合成 filler + 概括 | **112.3** | 3.94 | 58.8% | ⚠️ **复读退化** |
| 《红楼梦》引原文（本地） | **139.5** | 4.91 | 78.1% | ⚠️ **复读退化** |
| 《红楼梦》问答（全本） | **145.1** | 5.10 | 82.0% | ⚠️ **复读退化** |

## 2. 怎么识别退化（复读循环）

直接看输出文本。两个实例：

```
# 139.5 tok/s 的那条
'---\n请直接输出原文，不要解释。# 原文\n- 原文\n- 原文\n- 原文\n- 原文\n- 原文 ...'

# 145.1 tok/s 的那条
'【注意】请先阅读小说全文，再作答。若无法阅读全文，请说明原因。若无法阅读全文，请说明原因。若...'
```

模型卡在重复同一小段，重复 token 对草稿模型来说**极易预测** ⇒ 接受长度飙到 4.9–5.1。
这类"吞吐"不代表任何真实负载能力。

## 3. 对测量的要求

1. **不要只报一个数**。至少报 `(任务类型, tok/s, 接受长度)` 三元组；
   或报同一任务下的多请求分布（中位数 + 分位）。
2. **必须看输出**。凡是接受长度异常高（> 3.5）的样本，先确认是不是复读；
   确认退化后要么剔除，要么标明。
3. **对比必须同内容**。换 prompt 就等于换了工作负载——本文档开头那 3.2× 的差异
   全部来自内容，与配置无关。
4. **长度口径要精确**。用服务端 `/tokenize` 校准到正好 N 个 token，
   不要按"中文 ≈ 1 token / 1.7 字符"估（实测是 1.50，会差 16%）。

## 4. 本项目采用的口径

并发吞吐表（README §3.2）用《红楼梦》正文切片 + 四个**短切片可答**的问题轮换，
每条 prompt 精确 1024 token：

| 后缀 | 任务 |
|---|---|
| `data/hlm_local/local_quote.txt` | 摘录本段内的句子 |
| `data/hlm_local/local_qa.txt` | 抽取式问答（问本段人物/情节） |
| `data/hlm_local/local_continue.txt` | 接着本段续写 |
| `data/hlm_local/local_extract.txt` | 统计本段词频 |

**为什么不用 `data/hlm/suffix_*.txt`**：那四个是为**全本**设计的（"引第五回原文"、
"三人的感情走向"、"贾府兴衰"、"全书词频 Top10"）。配 1024 token 短切片时
3/4 在给定上下文里无解 —— 模型会回避或编造，落进复读的概率显著升高。

> 注：无解本身**不直接**决定吞吐。实测"无解问题"与"本地可答问题"在同类任务下
> 吞吐接近（47.3 vs 46.9 tok/s）——决定性因素是模型最终**是否掉进复读**。
> 用可答的问题是为了让"模型在正常完成工作"这一前提成立，而不是为了调数字。

## 5. 复现

```bash
# 逐任务拆解（会打印每个任务的实际输出开头，便于人工判断是否退化）
python3 tools/bench_concurrency.py \
  --base-url http://127.0.0.1:8020 --model deepseek-v41 \
  --concurrency 1,2,4,8,16,32,64 \
  --prompt-tokens 1024 --output-tokens 256 --repeats 3 \
  --suffix-dir data/hlm_local
```
