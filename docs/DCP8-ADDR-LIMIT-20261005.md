# ★ DCP8 寻址上限收官：**120,012 块 / 15.36M token 全部正确**（2026-10-05）

> 背景：KV32 守卫用 `CED 单组页步长 147712 B` 校准出上界 **29,076 块**（`⌊2³²/147712⌋`）。
> 但 DCP8 的池是 **133,917 块**，远超这个上界 ⇒ 若 29,076 是 DCP8 的真上界，
> 那么块号 ≥29,076 的访问会 **32 位回绕**，症状是"HTTP 200 + 1 token（EOS）"的**静默错误**。
> 本文用四组压测给出**实测上界**。

## 1. 四组实验（全部 N 条并发、每条精确校准、各打一根唯一针、语料窗口互不重叠）

| # | 配置 | 块数 | 结果 | 结论 |
|---|---|---:|---|---|
| 1 | **4 × 960K** | 30,001 | **4/4 PASS** | 30,001 > 29,076 ✅ 该上界对 DCP8 不成立 |
| 2 | **7 × 128K**（对照） | 7,003 | **7/7 PASS** | 低块数基线正常 |
| 3 | **7 × 960K** | 52,505 | **7/7 PASS** | 上限 > 52,505 |
| 4 | **16 × 960K** | **120,012** | **16/16 PASS** | **上限 > 120,012（占池 89.6%）** |

实验 4 的原始判决（`~/tmp/boundary16.log`，墙钟 4211.5 s）：

```
VERDICT: 16/16 PASS   实占总 token ≈15361604（≈120012 块）
  [PASS] req0  码=Q66Z-9458 prompt=960100 tok  含本码=True 含他码=[]
  …（16 条逐条列出，全部"含本码、不含他码"）
```

* 16 条各 960,093–960,102 token（合计 **15,361,604 token**），**每条的答案都只含自己的针**；
* **无 1-token EOS、无乱码、无跨请求串扰** —— 回绕的特征一个都没出现。

**实验 3 的措辞很关键**：第一次做 7 × 960K 时用的是"唯一令牌"措辞，得到 4/7
（2 条拒答 + 1 条输出章回标题）；换成**已在实验 1 验证过的"门禁密码"措辞**后
**7/7 全过**，唯一变量是措辞。
⇒ **那 3 个失败是措辞/拒答行为，不是寻址错误**（回绕的特征是 1-token EOS 或乱码，不是"礼貌拒答"）。

## 2. 逐步收紧的下界

| 观测 | 已验证正确 |
|---|---:|
| 4 × 960K | 30,001 块 |
| 7 × 960K | 52,505 块 |
| **16 × 960K** | **120,012 块** |
| 池容量 | 133,917 块 |

⇒ **DCP8 的每块页步长 < 2³²/120,012 = 35,788 B**（而 CED 的绑定页步长是 147,712 B
⇒ DCP8 明显更小，与 DCP 把序列维按 8 路分片一致）。

**与代码一致的解释**（`kv_cache_interface.py:105-110`，DCP overlay）：
```python
dcp_world_size = vllm_config.parallel_config.decode_context_parallel_size
# Note(hc): each dcp rank only need save (max_model_len//dcp_world_size) tokens locally.
if dcp_world_size > 1:
    max_model_len = cdiv(max_model_len, dcp_world_size)
return cdiv(max_model_len, self.block_size) * self.page_size_bytes
```

## 3. 对交付的影响

1. **`_ced_max_blocks=29076` 对 DCP8 是错的**（假通过）—— 已在 `serve_a2.sh` 的 KV32 守卫里
   改成"优先用 `GPU KV cache size ÷ block_size` 算**精确块数**"，并在 DCP 形态下**只警告不拦截**；
   本实验把"只警告"的**依据补全了**：29,076 这个常数在 DCP8 下**低估了 4.1 倍**。
2. **已验证可安全使用的上限：120,012 块（15.36M token 并发）**，占池 **89.6%**；
   剩下的 10.4% 是同一机制的连续外推（每块页步长恒定），没有新的结构风险。
3. 结论一句话：**DCP8 的容量是"真的能装满并用对"，不是"算出来很大但不敢用"。**

## 4. 方法学（可复用的三条）

* **措辞是干扰变量**：长上下文 + "请输出唯一令牌"这类措辞会触发拒答，
  而拒答**看起来像**失败但其实是行为；必须用"已验证不易拒答"的措辞做对照（本实验做了）。
* **判据要挑对**：回绕的特征是 **1-token EOS / 乱码 / 跨请求串扰**；
  **礼貌拒答、输出章回标题都不是**。四组实验里从未出现前者。
* **必须各打不同的针**：这次 16 条用 16 个互不相同的随机码 ⇒ 同时覆盖"跨请求串扰"。
