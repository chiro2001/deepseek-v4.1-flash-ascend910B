## 1. ★ K 因子更正：不存在 1.63× 膨胀

### 1.1 证据

我采了一份**纯 conc=1** 的新 profile（tp8k5，30 s 稳态，1024 prompt / 3072 out，不重启服务）。

**步锚点**：`allgatherAicpuKernel` 在新 profile 里只有 **5 次**（<6，不适用），
改用 **`HcPre` ÷ 86**：`159874 / 86 = 1859`（**整除**），与旧 profile 的 86 次/步一致。

结果：

| 量 | 值 |
|---|---:|
| 窗口内步数 | 1854 |
| **步长（profile）** | **25.458 ms** |
| 步长（同服务同负载实测，`/metrics` 差分） | **24.860 ms** |
| **K = 25.458 / 24.860** | **1.024** |
| 脚本按 24.59 归一 → 报 K | 1.035 |

⇒ **profile 时间 ≈ 真实时间。**

### 1.2 那旧的 1.6275 是怎么来的

旧 profile（`armF_r6_base`）来自 `prof_conc.sh 1,4,8` —— **一个窗口混了三个并发相位**。
其"步长"40.02 ms 是**相位平均**（conc=1 的 ~25 ms 与 conc=8 的 ~41.5 ms 之间偏后者），
拿它除以"conc=1 的 24.59 ms"就得到了假的 1.6275。

**佐证**：旧 profile 里 `HcPre` 的形状是 `48/42/36/30,4,5120` 混合
（= 8/7/6/5 个请求 × 6 token 的不同相位），而新 profile 是**单一形状 `48,4,5120`**。

### 1.3 影响面（要更正的历史结论）

| 文档里的说法 | 更正 |
|---|---|
| "真实步长 24.59 ms，profile 步长 40.02，K=1.6275" | 40.02 是**混合相位步长**，不是膨胀后的 conc=1 步长 |
| 各算子的"真实暴露 = 暴露/1.6275" | **口径不明**（分子分母不同相位）。纯 conc=1 下无需换算 |
| "AIC 忙 22.05 ms（55%）" | 纯 conc=1 是 **14.655 ms（57.6%）**；**百分比相近，绝对值差 1.5×** |
| "AIV 忙 14.75 ms（37%）" | 纯 conc=1 是 **7.527 ms（29.6%）** |
| "通信 4.21 ms（11%）" | 纯 conc=1 是 **2.818 ms（11.1%）** —— **百分比一致** |

**结论**：**结构结论（零重叠、算子数主导、带宽利用率低）全部不变**；
但**绝对毫秒数**要按新数据来。百分比大多相近，因为分子分母都是同一相位的。

## 2. 纯 conc=1 的真实资源账（新基准）

**口径**：tp8k5、`MAX_SEQS=32`、`BAT=8192`、`SPEC=1 K=5`、`ENGRAM_DEVICE_INDEX=1`、
**纯 conc=1**、30 s 稳态、步锚 `HcPre/86`、步长 **25.458 ms**、**2,821 个算子/步**。

| 资源 | busy ms/步 | 占步长 |
|---|---:|---:|
| **AIC** | **14.655** | **57.6%** |
| **AIV** | **7.527** | **29.6%** |
| **COMM** | **2.818** | **11.1%** |
| AICPU | 1.521 | 6.0% |
| **全并集** | **23.978** | **94.2%** |
| **纯空闲** | **1.480** | **5.8%** |

**重叠矩阵（ms/步）**：

| ∩ | AIC | AIV | COMM | CPU |
|---|---:|---:|---:|---:|
| **AIC** | 14.655 | **1.826** | **0.000** | 0.128 |
| **AIV** | 1.826 | 7.527 | 0.018 | 0.470 |
| **COMM** | **0.000** | 0.018 | 2.818 | 0.118 |
| CPU | 0.128 | 0.470 | 0.118 | 1.521 |

### 2.1 三条读法

1. **`COMM ∩ AIC = 0.000`（仍是精确零）** ⇒ 集合通信与 cube **完全无重叠**，结构性结论不变；
2. **AIV 只有 7.527 ms，其中 1.826 已与 AIC 重叠** ⇒ **未重叠仅 5.70 ms**。
   把这块全藏进 AIC 空闲（10.80 ms）⇒ 步长 **25.458 → 19.76 ms = 1.29×**。
   （这是"多流/AIC-AIV 流水"的**真实上界**，比旧文档引的 1.39×/1.81× 更贴近 conc=1 实况。）
3. **"全资源完美重叠"只有 1.06×** —— 因为全并集已达 **94.2%**，
   **设备几乎没有空闲可填**。⇒ 想变快**只能减少工作量**（这正是融合路线的依据），
   不能靠"填气泡"。
