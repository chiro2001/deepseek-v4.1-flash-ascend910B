## 1. 指标口径（已对齐）

```
A        = 接受长度
A_out    = 1 + A        每路每步产出 token
ms_step  = 引擎侧步周期（[bneck] hp 或 /metrics 差分）
每路 tok/s = A_out / ms_step × 1000
聚合 tok/s = N × 每路
```

| 规则 | 内容 |
|---|---|
| **主指标** | **单流 ms/step**（不受 A 影响） |
| **tok/s** | 只用地火口径报；否则一律 ms/step |
| **跨档比较** | 只看 **ms/step**（或**步长膨胀**）；`A` 随内容变动，tok/s 不可跨档比 |
| **换算** | 聚合 = 每路 × N；每路 = 聚合 ÷ N；单流→N 并发 = 单流 × A_out 增益 ÷ 步长膨胀 |

**关键实测（同语料受控，地火 × 统一 continue 任务）**：

| conc | ms/step | A | A_out | 每 token 延迟 |
|---:|---:|---:|---:|---:|
| 1 | **24.860** | 1.66 | 2.66 | 9.35 ms |
| 8 | **41.890** | 2.16 | 3.16 | **13.26 ms** |

⇒ **步长膨胀 ×1.685**（跨语料可比的纯结构量）；每 token 延迟 **+41.8%**（实测）/ **+68.5%**（A 归一化）。
⇒ 之前报的"8 并发损失 13%"是**混入 A 增益**的结果；固定任务后是 **29.5%**。

## 2. 步长解剖（单流 24.59 ms 的构成）

### 2.1 24.6 ms **包含**推测解码（已确认）

| 配置 | `[bneck] hp` | 佐证 |
|---|---:|---|
| **SPEC=0**（`armNOSPEC2_1006_231507`） | **17.729 ms** | `speculative_config=None`，dspark 日志 0 次 |
| **SPEC=1**（`armFINAL_1006_235454`） | **24.614 ms** | dspark 日志 317 次 |
| **Δ** | **+6.89 ms** | |

**机制**：`mark_step()` 在 `prepare_engram_inputs()` 里，由 runner 在 `run_model()` **之前**每步调用一次
（源码注释自证）⇒ `hp` = 完整步周期。**交叉验证**：`/metrics` 差分 24.793 vs bneck 24.590（差 0.8%）。

> 更正：用户记忆中的"24 ms"是**旧配置的 SPEC=0 基线**（CED-PD 拓扑，24.35 ms），
> 与当前 TP8 单体的 17.73 ms **不同拓扑，不可相减**。

| 资源 | busy | 占步长 | 与 AIC 的重叠 |
|---|---:|---:|---:|

| AIV（48 vector/die） | 14.75 ms | 37% | **仅 3.50 ms** |

AIC 闲 17.97 ms = 等 AIV 11.25 + 通信 4.21 + AICPU 2.07 + 噪声 0.43

## 4. AIC‖AIV 并行：为什么能、为什么现在没有

### 4.1 机制（三层）

| 层 | 内容 |
|---|---|
| **硬件** | AIC（24 cube）与 AIV（48 vector）是**两套独立算术通路**，天然允许同时工作 |
| **调度** | NPU **没有乱序引擎**，图里写什么顺序就按什么顺序发 ⇒ **单流 = 零 ILP**（实测串行下界 3.075 vs 实测 3.082，差 0.2%） |
| **队列** | 给了独立工作后，**硬件按资源排队，队列天然把相位错开一位**——不需要显式错相位 |

**上界（纯算术）**：串行 = `AIC + AIV`；完美重叠 = `max(AIC, AIV)`。
真实口径 24.59 → **13.55 ms（1.81×）**。

**微基准实证**（图内、同工作量切 k 条独立链）：6 流 **1.37×**（上界 1.46× 的 **94%**）；8 流回落 1.26×。

### 4.2 卡在哪：**缺独立工作，不是缺机制**

| 候选来源 | 判定 | 原因 |
|---|---|---|
| 同一 batch 的下一层 | ❌ | 272 对 AIC↔AIV **直接依赖**交替 |
| 跨层（层 L 的 AIV ‖ 层 L−1 的 AIC） | ❌ | **层边界吃上一层最后一个算子的输出**；层内 8 个转换也全是真依赖 |
| draft ‖ verify | ❌ | draft 依赖 verify 结果，且**已串在主流上**（43 层 = 40 主层 + 3 draft） |
| 跨请求 | ❌ | **不存在**（所有请求同一条流）；且改成独立前向需 `8 × 13.55 = 108 ms` AIC vs 批处理 41.5 ms ⇒ **批处理好 2.6×** |
| **跨 micro-batch** | ❌ | **账是负的**（见 §5） |
| **层内支路** | ✅ **已在做** | 我们的 `dsa_v1.py` 有 **4 个 `npu_stream_switch` 挂载点**；官方 `limit_core_num` 5 个使用点全是同类 |
| **engram `AivKernel` ‖ HCCL** | ✅ **已跑通** | 4.11 ms **100% 与集合通信并行**——唯一真正的重叠先例 |

### 4.3 跨 micro-batch 为什么账是负的（核心算术）

| | AIC | AIV | 步长 |
|---|---:|---:|---:|
| 不拆批、串行（现状） | 22.05 | 14.75 | **36.8 ms** |
| 不拆批、完美重叠（**做不到**） | — | — | max = 22.05 ms |
| **拆 2 份、完美重叠** | **44.10** | **29.50** | **44.10 ms** |

```
拆批增加的工作量 = AIC + AIV = 36.8 ms
重叠最多能省下的  = min(AIC, AIV) = 14.75 ms
⇒ 代价是收益的 2.5 倍
```

**三个具体来源**：
1. **权重重读**：MoE 是权重带宽受限（token 涨 64× 耗时只涨 4%）⇒ 半批照样读整份专家权重；
2. **通信翻倍**：81 次 → 162 次，且**每次价格不变**（60 KB 与 2 MB 同价，纯固定延迟）⇒ **+4.2 ms**；
3. **固定开销翻倍**：~1,000 个小算子是每步固定成本。

**且实测已排除"重叠没生效"**：图内串行 vs 图内并发曲线**完全重合**（58.0/57.7、75.1/73.9）
⇒ 那 −42% **全是拆批代价**（conc=4/8 掉到 **0.60× / 0.58×**）。

## 5. 今天新发现的**真实机会**：小算子海融合

每步 **2,888 个算子**中，**2,048 个（71%）属于可融合族**；**聚合真实暴露 4.708 ms = 19.1% 步长**。

| 融合族 | 次数/步 | 中位/算子 | **真实暴露** | **占步长** | 4:1 融合可省 |
|---|---:|---:|---:|---:|---:|
| **F3 norm + quant** | 370.1 | **10.52 µs** | **1.127 ms** | **4.6%** | 1.794 ms |
| **F2 dtype / 搬运链** | **491.1** | **1.44 µs** | **0.888** | 3.6% | 0.326 ms |
| **F7 RoPE / 取表链** | 197.0 | 8.82 µs | **0.877** | 3.6% | 0.801 ms |
| F8 归约 / 逐元素杂项 | 155.0 | 3.84 µs | 0.437 | 1.8% | 0.274 ms |
| **F6 indexer 小 kernel** | 24.0 | 19.72 µs | 0.403 | 1.6% | 0.218 ms |
| **F4 MoE 路由链** | 129.0 | 13.10 µs | 0.384 | 1.6% | 0.779 ms |
| **F1 位置 / 槽位链** | **469.3** | **1.54 µs** | 0.356 | 1.4% | 0.333 ms |
| F5 spec-decode 后处理 | 42.0 | 10.67 µs | 0.236 | 1.0% | 0.207 ms |
| **合计** | **2,047.6** | — | **4.708 ms** | **19.1%** | ≈4.73 ms（乐观） |

**三个读法**：
1. **数量最多的不是收益最大的**：F1+F2 有 960 个/步（33%），但中位只 1.44~1.54 µs，合计暴露 1.244 ms；
2. **F3 是单项最大**：只有 370 个/步，但中位 10.52 µs（是 F1/F2 的 7 倍）——因为**每处 norm 后紧跟一次 quant**，天然成对；
3. **"4:1 融合可省"是乐观上界** ⇒ **现实按 40~50% 计，即 1.9~2.4 ms = 8~10% 步长**。

### 融合 vs 单算子暴露的区别（重要）

`DequantSwigluQuant` 的**单算子暴露只有 0.025 ms**（曾被判"已否决"），但按族统计它属于 F3。
两者不矛盾：**单算子暴露**衡量"单独删掉它能省多少"；**族统计**衡量"整族一起融能省多少"。
**融合的收益来自减少调用次数，所以要看族的次数，不能只看单算子暴露。**
