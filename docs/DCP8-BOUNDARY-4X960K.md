# ★ DCP8 边界测试：4 条并发 960K tokens（30,001 块 > 29,076）**4/4 正确**（2026-10-04）

> 本文回答 `DCP8-CAPACITY-20261004.md` §5 提出的风险：
> KV32 守卫用**非 DCP 口径**的 `bytes_per_block=540928` 估算，对 DCP8 会**假通过**
> （它算出 22,863 块 ≤ 上界 29,076，而实际是 133,924 块）。
> 若 29,076 真的是 DCP8 的寻址上界，那么块号 ≥29,076 的访问会 **32 位回绕**，
> 症状是"HTTP 200 + 1 token（EOS）"的**静默错误**。

## 1. 实验设计（压到边界以上）

用 `~/tmp/boundary2.py`：**4 条并发请求，每条精确校准到 960,04x tokens**
（先二分截断语料再插针，`/tokenize` 校准，目标 960,000 tok）。

| 量 | 值 |
|---|---:|
| 并发数 | 4 |
| 每条 prompt | **960,038 – 960,046 tokens** |
| **合计 token** | **3,840,166** |
| **合计块数（÷128）** | **≈30,001 块** |
| 上界（守卫口径） | 29,076 块 |
| **是否越过边界** | **是（+3.2%）** |

**关键是四条请求各打一根不同的针**（A/B/C/D，语料窗口互不重叠、无前缀复用），
因此判据是硬的：每条**必须**答出自己的针，且**不得**含别人的针
（能同时检出"静默错答"与"跨请求串扰"）。

## 2. 结果：**4/4 PASS**

```
发起 4 条并发 × 960000 tok（合计 ≈30000 块）
总墙钟 991.8s
  [PASS] 针A prompt=960046 tok  991.5s 含本针=True 含他针=[] 答='ZQ7K-3341'
  [PASS] 针B prompt=960045 tok  991.5s 含本针=True 含他针=[] 答='VX2M-8890'
  [PASS] 针C prompt=960045 tok  991.8s 含本针=True 含他针=[] 答='…HT4P-5527…'
  [PASS] 针D prompt=960042 tok  991.6s 含本针=True 含他针=[] 答='…RB9N-6014…'
VERDICT: 4/4 PASS
```

**⇒ 结论**：
1. **29,076 不是 DCP8 的寻址上界** —— 30,001 个不同块被正确寻址、正确回读；
   说明 DCP 把每个 KV group 按 8 路分片后，**页步长相应变小** ⇒ 真实上界远高于 29,076。
   （`DCP8-CAPACITY` §5 里"守卫对 DCP8 假通过"这条**仍然成立**——守卫的常数确实不对——但
   **不构成实际风险**，因为真实上界比它高。）
2. **④ 容量的端到端验证**：**4 条 960K 并发请求同时驻留并全部正确**
   —— 这是目前对"DCP8 能装下超长上下文"最直接的证据（远超 TP8 的 2.82M 总容量）。
3. **并发正确性**：四条不同针互不污染 ⇒ 这条同时覆盖了"并发 2 不同针"的更强版本。

## 3. 一个待办（低优先级，但应记账）

**KV32 守卫对 DCP8 的常数应当修正**（现在用 `540928 B/块`，DCP8 实际 ≈`92,362 B/块`）。
影响：**假通过**（把危险当安全）。本次实验证明当前配置安全，但如果将来把
`GPU_UTIL` 或 `MAX_LEN` 调得更大，守卫**不会**给出正确预警。
建议：在守卫里按 `decode_context_parallel_size` 折算 `bytes_per_block`，
或直接在 DCP8 形态下用它自己打印的 `GPU KV cache size` 反算块数并与上界比。

## 4. 本次实验的工程细节

* 4 条 960K 请求的 **prefill 被 admission gate 串行化**（实测 `Running=1, Waiting=3`），
  总墙钟 **992 s ≈ 4 × 248 s**，每条各 248 s 左右 ⇒ **prefill 串行是设计行为**（gate 保证
  prefill-only 步不含 decode），不是卡顿。
* 第一次尝试（`boundary_4x1m.py`）用粗糙的"按字符数拼"导致 3 条超长，被服务
  以 **HTTP 400** 拒绝（4–8 s 内返回）—— 注意**这与回绕的症状完全不同**：
  回绕是 HTTP 200 + 1 token，超长是 HTTP 400 立即返回。判据要分清这两者。
* 工具：`~/tmp/boundary2.py`（可复用；参数 `<port> <target_tokens> <n_conc>`）。
