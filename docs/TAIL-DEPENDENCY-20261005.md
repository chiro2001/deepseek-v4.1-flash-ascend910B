# 尾部（N=8 的 19%）是**真实数据依赖链**，不是调度问题（2026-10-05）

> 背景：N=8 的步长 40.21 ms 里，主图只占 25.5 ms；剩下的 **7.6 ms 尾部**是第二大项
> （19%）。此前只知道"主图空闲、别的流在跑"，本轮把**依赖关系**查清了。
> 数据：`armF_r7_wkvtp` 的 N=8 捕获（s109=主图，s47=采样链，s105=draft，s35=metadata）。
> 标注：【实测】/【推断】。

## 1. 步内相位（中段 8 步的并集区间，按 gmm1 锚点归一）

| 流 | 身份 | 步内相位 | 跨度 |
|---|---|---:|---:|
| s47 | **采样链**（LM head → 采样准备 → 拒绝采样） | **79.1% → 98.4%** | **19.3%** |
| s105 | **DSpark draft**（3 层） | 82.7% → 92.6% | 9.9% |
| s35 | metadata（7 次 AICPU） | 95.3% → 99.1% | 3.8% |
| s110 | engram 回程等 | 95.6% → 98.3% | 2.7% |
| s108 | allreduce（贯穿全步 81 次） | 0.7% → 99.7% | 99.0% |

⇒ **s47 横跨整个尾部**（79%→98%），但**只干 2.23 ms 的活** ⇒ 它内部有大量等待。

## 2. s47 内部的两段大等待 = **在等 draft**

s47 内部 ≥50 µs 的空隙合计 **5.24 ms**，其中：

| 空隙 | 前驱 → 后继 | 归属 |
|---:|---|---|
| **4.046 ms** | `aclnnInplaceCopy_Cast` → `aclnnInplaceFillScalar_Fill` | **等 draft 出结果** |
| **1.083 ms** | `Fill` → `aclnnInplaceZero_ZerosLike` | 采样后处理 |
| 0.111 ms | `Matmul` → `Transpose` | — |

**现场（单步，步内相对时间）**：

```
t=79.12%  31.415 ms  MatMulV2 "48,5120;16160,5120"   0.192 ms   ← LM head（vocab 分片后）
t=79.88%  31.718 ms  Transpose                       0.034
t=80.16%  31.831 ms  Index (取 last-token logits)    0.105
t=81.36%  32.308 ms  copy_and_expand_..._dspark      0.052
t=82.07%  32.589 ms  SparseAttnSharedkvMetadata      0.223
           ↓ 4.05 ms 空隙（s105 draft 正在跑：82.7%–92.6%）
t=92.91%  36.893 ms  Fill                            0.002
           ↓ 1.08 ms 空隙
t=98.21%  38.996 ms  ZerosLike "8192"                0.002
           下一步的主图在 100% 开始
```

⇒ **依赖链是**：`LM head → 采样准备 → (等 draft 3 层) → 拒绝采样 → 下一步主图`。
这是**真实的数据依赖**：拒绝采样必须拿到 draft 的 logits 才能判定接受/拒绝，
**无法通过重排调度消除**。

## 3. 为什么"draft 很贵但必须留"

| | 有 draft（现状） | 无 draft（反事实） |
|---|---:|---:|
| 步长 | **40.2 ms** | ~36.2 ms（省掉 draft 的 ~4 ms） |
| 每步产出 | **A ≈ 2.5 token** | 1 token |
| 单流吞吐 | **≈ 62 tok/s** | ≈ 27.6 tok/s |

⇒ **draft 是 2.25× 的净收益**，尽管它占了 10% 的步长。
（这解释了为什么之前测的 `SPEC_MODE=off` 在高并发**反而更差**的说法只在小样本下成立——
真正的账要按 A 一起算。）

## 4. 由此排除的"尾部优化"清单

| 想法 | 判定 | 依据 |
|---|---|---|
| 把 metadata 提到 draft 之前跑 | ❌ **不行** | metadata 的相位已是 95.3–99.1%，且它需要采样后的 `seq_lens`；提前不了 |
| 让 s47 与 s105 并行 | ❌ **不行** | §2 的依赖链：拒绝采样必须等 draft |
| 缩短 draft 层数 | ❌ 不可配 | 3 层由模型/checkpoint 定义（`dspark_target_layer_ids=[37,38,39]`） |
| 缩短 K（`SP_TOKENS`） | ❌ 已测 | R5：K=7 / K=3 都比 K=5 慢（每位置接受率 0.75/0.50/0.32/0.17/0.12 ⇒ 后段几乎不被接受） |
| 把尾部与下一步主图重叠 | ❌ 不行 | 下一步主图需要采样结果（token id + KV 写入位置） |

**结论**：尾部的 19% 在本架构下**不可压缩**（除非改 draft 模型本身，例如更小的 draft 或
更少层数的 draft）。这把它从"待优化靶点"正式移出。
