# decode bound 拆解 v2：**5 个算子占 58% 真实暴露**，小算子海只占 11.5%（2026-10-07）

> 数据：纯 conc=1 新 profile（tp8k5，`armHANDOVER_1007_015350`，步锚 `HcPre/86`，
> 1857 步，步长 **25.458 ms**，**2821 算子/步**）。全部【实测】。
> 新增工具：`tools/prof_decode_bound_decomp.py`（六层分解）、暴露度扫描（仅独占段计入）。
>
> ⚠️ 本文**修正**此前"2888 个算子的串行链 = 瓶颈"的叙事——那个说法掩盖了真正的集中度。

## 0. 一页纸

| 层 | 结论 |
|---|---|
| **步长** | 25.458 ms = Σ算子时长 29.823 ÷ 并发度 **1.171** |
| **四桶** | 数学 7.4% / 标量 31.5% / 搬运 40.8% / 未归因 37.5% |
| **尺寸分布** | **>20µs 的算子（仅 13.4% 数量）占 Σ时长 57.8%**；<5µs 的（52.3% 数量）只占 **11.5%** |
| **★ 暴露度** | 独占时间 = 步长的 **72.2%**；**Top-5 算子 = 10.62 ms = 全部暴露的 58.3%** |
| **MTE 有效性** | MTE 窗口内有效带宽 **≤422 GB/s = 峰值的 26%** ⇒ **延迟受限，不是带宽受限** |

## 1. 方法（六层递进）

```
① 步长        = Σ算子时长 ÷ 并发度             （发现 171% 的并发度只有 1.171）
② 四桶        = 数学 / 标量 / 搬运 / 未归因      （per-op 子计数器，不用形状估字节）
③ 尺寸分布    = 按算子时长分桶                  （定位"大算子 vs 小算子海"谁是真成本）
④ 暴露度      = 时长中【整机只有它在跑】的部分    （区分"昂贵但被掩盖"与"昂贵且暴露"）
⑤ MTE 有效性  = 搬运窗口内的有效带宽            （判断是"搬得多"还是"搬得慢"）
⑥ 单算子构成  = Top-5 的标量/MTE 拆解           （给出可攻击的具体位置）
```

> ⚠️ **方法修正记录**：暴露度第一版实现有 bug（`expo[nm]+=L` 在并发度 >1 的段也累加），
> 导致 `AivKernel` 误报 99% 暴露。修正为"仅独占段计入"后，`AivKernel` 退出 Top-18
> —— 这与既有结论"`AivKernel` 100% 与 HCCL 并行"**一致**，反而验证了修正的正确性。

## 4. 层 ⑤：MTE 是延迟受限，不是带宽受限

| 项 | 值 |
|---|---:|
| 每步搬运 | 4.38 GB（解析式，已与 `npu-smi` 178 GB/s 交叉验证） |
| 整步平均带宽 | **172.1 GB/s（10.6% 峰值）** |
| Σ MTE 活跃 | 10.382 ms（占 Σ算子时长 34.8%） |
| **⇒ MTE 窗口内有效带宽（上界）** | **421.9 GB/s（26.1% 峰值）** |

**⇒ 即使把所有搬运都压进 MTE 活跃窗口，利用率也只有 26%。瓶颈是搬运的"启动/寻址延迟"，不是带宽。**

### 5.1 三种签名 ⇒ 三种不同的修法

| 签名 | 算子 | 特征 | 可能的修法 |
|---|---|---|---|
| **A. 纯搬运受限** | `MatMulV2`（MTE 91%） | 每算子读 8.4~10.5 MB 权重，18.7 µs ⇒ **449~561 GB/s（28~35% 峰值）** | 提高搬运效率：更大粒度的事务、L2 复用、权重常驻 |

| **C. 混合 + 等待** | `HcPre`、`SparseFlashMla` | 标量 ≈ MTE ≈ 10~12 µs，另有 0.76~1.03 ms 未归因 | 需要 kernel 级重构 |

## 7. 结论与可动性排序

**decode 的 bound 是一句话**：

> **5 个算子（`HcPre` / MoE w1w3 / `MatMulV2` / MoE w2 / `SparseFlashMla`）占 58.3% 的真实暴露，
> 而它们的数学只占自身时长的 4.8%。瓶颈是标量与搬运的延迟，不是算力。**

**可动性排序**（按"暴露量 × 可行性"）：

| 序 | 目标 | 暴露 | 依据 | 难度 |
|---:|---|---:|---|---|
| **1** | **两个 MoE 算子的标量开销** | 4.22 ms | 标量 2.718 ms；**与 token 数几乎无关**（conc 1→8 时长仅 +12%）⇒ 是纯固定开销 | 中高（kernel 改） |
| **2** | **`MatMulV2` 的搬运效率** | 2.26 ms | MTE 2.077 ms，有效带宽仅 28~35% 峰值 | 中（访存优化/权重布局） |
| **3** | **`HcPre` 内部** | 2.85 ms | 标量 11.8 + MTE 10.8 µs/算子；暴露度未测（此前探针失败） | 高 |
| **4** | `SparseFlashMla` 的未归因 | 1.29 ms | 未归因 1.029 ms | 未探明 |
| **5** | 小算子融合 | ≤3.4 ms | Σ时长 3.415 ms 是上界 | 高（多合1） |
