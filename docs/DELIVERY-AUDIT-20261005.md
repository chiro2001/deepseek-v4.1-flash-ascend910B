> 起因：`ENGRAM_WKV_TP` 的实现（`patches/files/model.py`，40 行）**只存在于工作区和已构建镜像**，
> git 里根本没有 —— 而启动器默认早已是 `=1`。任何人克隆分支部署都会**静默**退回旧行为
> （少 0.57 ms/步、少 5.9% 容量）。
> 顺着这条线做了三轮系统审计，共修掉 4 个缺口，并留下一个**可执行的门禁**。

## 2. 新增门禁：`tools/audit_fresh_clone.sh`

从**全新 clone** 出发做静态自检，三层：

| 层 | 查什么 | 当前结果 |
|---|---|---|
| ① | `git archive` 出干净副本（不依赖工作区） | 2700 个文件 |
| ② | **实际挂载/执行**的路径是否都在 clone 里（`-v "$X:..."`、`bash "$X"`、`[ -f "$X" ]`） | **43/43 存在**，9 项按文档化可选跳过 |
| ③ | 交付默认的**代码级**特征逐条存在（wkv 分片实现、两个默认值、哑开关透传、EPLB 接线、内核烘焙、armF 内核文件、稳定桶提醒…） | **12/12 ✅** |

```bash
bash tools/audit_fresh_clone.sh          # exit 0 = 通过；KEEP=1 保留临时 clone 供复核
```

**设计上的两个教训已内置**：

* **不用 `/tmp`**：`/tmp` 是本机 tmpfs（8 GB），clone 目录会把它打满
  （实测：7 个 clone 占 1.9 GB 后 `/tmp` 100% 满，连 heredoc 都写不进去）⇒ 改用 `~/tmp` + `trap` 自动清理。
  这与本项目既有纪律（"产物放 `~/tmp`，不用 `/tmp`"）一致，我这次是违反了它才发现。
* **只认"真会被用到"的引用**：首版把注释里的路径也当依赖，报了 20+ 假阳性
  ⇒ 现在只抽 `-v` / `bash` / `[ -f ]` 三种形式，并对**文档化可选**项（PGO 二进制、PROBE 派生件、运行期目录）白名单。

## 4. 结论

* **四维度的交付默认，现在从"全新 clone"出发是可复现的**（门禁 exit 0）；
* 三个缺口都在**非交付默认路径**上（诊断件、EPLB 实验、动态-K），因此
  **当前运行中的实例从未受影响**（它一直用 a3-21 的工作区文件，且 144K 11/11）；
* 但它们的**危害是真的**：任何按仓库部署的人都会踩。

**建议把这句写进发布流程**：

> 改完 `scripts/` 或 `patches/` 的任何东西，**先 `git commit`，再跑 `tools/audit_fresh_clone.sh`**；
> exit 非 0 不许发。
