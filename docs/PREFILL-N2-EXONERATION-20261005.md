# N=2 冷 prefill "4,167 tok/s 异常" = 测量事故（2026-10-05 晚）

> 交接遗留待办：发布镜像终验时 N=2 冷 prefill 记录过一次 `15.73 s / 65,543 tok = 4,167 tok/s`，
> 而 N=1/N=4 是 7,071 / 7,467。本文用日志取证 + 干净重测结案。

## 1. 结论

**4,167 是与其他负载重叠造成的受污染测量，未复现。**
N=2 冷 prefill 干净口径（服务空载、两条并行、32K×2、nonce 冷前缀）：

| 时间 | 条件 | 结果 |
|---|---|---|
| 10-05 05:26（`~/tmp/prefill_cold.log`） | 空载 | 9.10 s / 65,543 tok = **7,204 tok/s**（TTFT 9.04/9.09 s） |
| 10-05 16:2x（本文重测，无 profiler） | 空载（先验 running=0） | run0 **7,451** / run1 **7,427 tok/s**（TTFT 8.8 s×2） |
| 10-05 07:59 UTC（`armIMG_v3_restore6`，16:00 前终验窗口） | **与其它请求重叠** | **4,167**（名义值） |

⇒ ③ prefill 维度按干净口径 N=2 ≈ 7,204–7,451，**不是异常点**。

## 2. 污染证据（restore6/serve.log，07:59 UTC = 15:59 本地）

15.73 s 的记录对应 4 号 profiler 会话（`start 07:59:30 → stop 07:59:49`，
stop 时点 ≈ t0 + 15.73 s + start/stop 开销，两项吻合）：

| 日志行 | 含义 |
|---|---|
| `07:59:37 Running: 2 reqs, Waiting: 2 reqs` | 系统内共 **4 条**请求 |
| `07:59:47 Running: 4 reqs, Waiting: 0` | 4 条同时在跑 |
| `07:59:27 Running: 0`（本会话开始前 3 秒） | 之前一波已清空 ⇒ 多出的 2 条是**新到的并发负载** |

旁证：同期还在跑 144K 验收与基准（`live_accept` / 四维 run，15:44–16:00），
其请求与冷 prefill 测试叠加；会话 #3（07:59:04–07:59:21）里也能看到
`Running 1, Waiting 1 → Running 2` 的排队细节。

## 3. 教训（写进测试纪律）

1. **任何 prefill/TTFT 类测量前，必须先查服务是否空载**
   （`vllm:num_requests_running == 0` 且 `waiting == 0`），并在测试窗口内确认没有第二个负载源。
2. 本项目的"四维基准"与"验收/其它探测"**不要并行发起**——互相污染（本次是第一次踩到的实例；
   `ab_gate` 的 n=18 过渡桶问题同源，都是"旁边有人在跑"）。
3. 重测脚本已入库：`tools/prefill_cold_noprof.py`（无 profiler 版，每轮重新生成 nonce 冷前缀；
   需要 profiler 版本继续用 `tools/capture_prefill_cold.py`）。
