# 决定性对照：CBP 的真身是 DP —— DP2TP1 扩展效率 99%，但绝对增益只有 4~9%（tiny）（2026-10-07）

> 承接 `S15`（DBO 两条流不并行 ⇒ 需要换载体）。
> 本文实测 CBP 的天然形态：**vLLM 原生 DP2TP1**（2 个独立实例，各一个请求，互不共享集合通信）。
> 环境：tiny（`dsv41-tinyspark`，2 chip），dummy 权重，SPEC=1 SP_TOKENS=7。全部【实测】。

---

## 0. 一页纸

| 项 | 结果 |
|---|---|
| **TP1 能跑通吗**（DP 的前提） | ✅ **能**（模型装得进 1 chip；只需把 DCP 从 2 降到 1） |
| **DP2TP1 能跑通吗** | ✅ **能**（`--tensor-parallel-size 1 --data-parallel-size 2`，80 s 起来） |
| **CBP 的扩展效率** | **tax = 1.010**（几乎完美；TP2 合并批是 1.143） |
| **CBP 的绝对增益**（同接受长度归一） | **conc=2: +4%；conc=4: +9%** |
| 与 DBO 对比 | DBO tax = **1.98**（❌）；DP tax = **1.01**（✅） |
| **结论** | **CBP 成立，但载体是 DP，不是 ubatching** |

## 3. ★ 接受长度是混淆项，必须归一

**两臂的接受长度不同**（TP2 = 1.00，DP2 = 2.00）——dummy 权重下 draft 表现随机，
TP1/TP2 的权重切分布局不同，导致接受率不同。

⇒ **原始 tok/s 不能直接跨臂比较**（DP2 的 2.08× 里绝大部分是接受长度的贡献）。

### 3.1 臂内扩展效率（接受长度自动抵消，**可信**）

| 臂 | conc=1 | conc=2 | **2× 扩展** | conc=4 | **4× 扩展** |
|---|---:|---:|---:|---:|---:|
| **TP2 合并批** | 38.1 | 66.7 | **1.75×** | 106.7 | **2.80×** |
| **DP2TP1（CBP）** | 70.1 | 138.8 | **1.98×** | 231.7 | **3.31×** |

**tax 定义**：`tax(N) = N × R₁ / R_N`（1.0 = 完美扩展）

| 臂 | **tax(2)** | **tax(4)** |
|---|---:|---:|
| **TP2 合并批** | **1.143** | **1.429** |
| **DP2TP1（CBP）** | **1.010** | **1.208** |

⇒ **CBP 的扩展效率显著优于合并批**（2 流时 99% vs 87.5%）。

### 3.2 归一接受长度后的绝对增益

把 DP2 的吞吐按接受长度归一（A=2.00 → 除以 2）：

| conc | CBP（归一 A=1） | 合并批（A=1） | **增益** |
|---:|---:|---:|---:|
| 2 | **69.4** | **66.7** | **+4.0%** |
| 4 | **116.4** | **106.7** | **+9.1%** |

| 载体 | tax(2) | 门槛 S(2)=1.137 | 判定 |
|---|---:|---:|---|

---

## 5. 为什么 DP 行、DBO 不行（机制）

| | DBO / ubatching | **DP2TP1** |
|---|---|---|
| 两条流之间共享什么 | **TP 集合通信域**（每步 91 次 allreduce/ubatch） | **什么都不共享** |
| 通信点是否同步 | ✅ 是（每步 ~182 次跨 ubatch 同步） | ❌ 无跨实例通信 |
| 实测并行度 | ❌ 两条主链几乎不重叠（S15） | ✅ 1.98× 扩展 |
| 算子数 | ❌ **2×**（每个 ubatch 跑完整前向） | ✅ 每实例 1×（但合起来也是 2×） |

**关键差别**：DP 的两个实例**在设备层面完全独立**，唯一的共享是 HBM 与算力；
DBO 的两个 ubatch 则被 TP 集合通信**强行锁在同一条时间线上**。

## 6. 局限（必须说明）

| # | 局限 | 影响 |
|---:|---|---|
| 1 | **tiny 模型能装进 1 chip** | DP 的代价（每实例一份完整权重）在这里几乎为零 |
| 2 | **真实模型（A3 上）必须 TP8** | DP2 要把**整个模型复制 2 份**，显存/权重加载代价完全不同 |
| 3 | dummy 权重导致接受长度不一致 | 绝对 tok/s 不可跨臂引用；已用"归一 + 臂内 tax"两种口径规避 |
| 4 | 只测到 conc=4 | 更高并发的税曲线未测 |

**⇒ "CBP 在 tiny 上成立（+4~9%）" 不能直接外推到 A3 的 TP8 场景。**

## 8. 复现

```bash
# CBP 臂（DP2TP1）
ssh a3-21 'bash /tmp/launch_tiny_dp2.sh'
# 合并批臂（TP2，DCP=1）
ssh a3-21 'bash /tmp/launch_armMcp1.sh'
# 测量（务必带 --metrics-url 以免接受长度取占位值）
ssh a3-21 'cd ~/cedpd-repo && python3 ~/tmp/bench_conc.py --base-url http://127.0.0.1:19310 \
  --model deepseek-v41 --metrics-url http://127.0.0.1:19310/metrics \
  --concurrency 1,2,4 --prompt-tokens 1024 --output-tokens 96 --repeats 3'
```

**踩坑记录**：
1. `TP=1` 必须同时把 `DCP` 降到 1（`tp_size=1 must be divisible by dcp_size=2`）；
2. 上一实例的**残留 worker 会占住 HBM**（53GB/12GB），导致下一实例 `Free memory ... less than desired GPU memory utilization` ⇒ **换配置前必须彻底清理**；
3. 相位配平补丁在**捕获期创建新流会破坏 ACL graph 捕获**（`MTE accesses an invalid GM address`）⇒ 必须只在非捕获期建流（已修正但仍默认关闭）。
