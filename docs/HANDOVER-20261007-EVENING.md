## 3. ⚠️ 未解异常（接手第一优先）

### 3.1 HcPre 暴露度探针：结果矛盾

| 臂 | 内核 md5 | 服务侧 bneck p50 | **单算子设备时长** |
|---|---|---:|---:|
| **ctl0**（SPIN=0） | `0e4c3e5c` | 24.996（n=1888） | **34.20 µs** |
| **spin2000** | `d48e8551` | 25.322（n=1360，**+1.30%**） | **34.20 µs** |

**矛盾**：服务侧 +0.326 ms，而单算子 bench **完全没变**。

已排除"bench 不读 OPP"：把 `ASCEND_CUSTOM_OPP_PATH` 设为不存在路径会报
`aclnnHcPre ... not in libopapi.so` ⇒ bench **确实**从该路径解析算子。

**两种解释未区分**：
1. spin 生效 ⇒ 暴露度 ≈15% ⇒ HcPre 优化只值 0.4 ms ⇒ **不值得做 kernel**；
2. spin 没生效（bench 证据）⇒ 服务 +0.326 是噪声（0.2 ms 漂移的 1.6 倍）⇒ **暴露度仍未测**。

**注意**：**加大 spin 不能区分**——服务侧只能测 `d(step)/d(iterations)`，测不到 `d(kernel_time)/d(iterations)`。

### 3.2 建议的解法（成本低）

**给探针加"可观测副作用"**：把 spin 计数写进 `workspace` 的一个保留位置（或某个输出张量的未使用字节），
重建 → 服务侧读回 ⇒ **直接确认内核是否被执行**，一举消除矛盾。

## 4. ⚠️ 两条未被利用的线索

### 4.1 `[KADAPT]` / `[HF32-HOIST]`：**未发布的 hc_pre 优化**

**位置**：`csrc/moe/hc_pre/op_kernel/hc_pre_cube_compute.h`（**非 arch35**）
镜像内嵌源码（`.../custom_transformer_impl/ascendc/hc_pre/`，8 文件）与容器 csrc 逐文件比对，**只有这一个文件不同**。

```cpp
// [KADAPT] 按 M 自适应选 L0 的 K 步长：M<=64 用 128、M<=128 用 64、其余 32
const uint64_t kL0Size_ = (mAligned_ <= 64UL) ? 128UL : ((mAligned_ <= 128UL) ? 64UL : 32UL);
// [HF32-HOIST] HF32 模式提到 K 循环外（省 32/8 轮重复 scalar）
AscendC::SetHF32Mode(1); AscendC::SetHF32TransMode(1);
```
（作者注释："三档都能整除 kL1Size，**不改变累加顺序**"）

**两个问题**：
1. **对我们形状可能无效**：M=6 ⇒ `kL0Size_ = 128`；而 K（`hc_fn` 首维 = 24）⇒ **K 循环本就只有 1 轮**，32 与 128 无差；HF32-HOIST 也无可省的重复轮次；
2. **可能根本没被编译**：`hc_pre.cpp` 按 `#if defined(__DAV_C310__)` 分支；**`hc_pre_cube_compute_arch35.h` 里 KADAPT/HF32-HOIST 出现 0 次**；构建日志里 arch35 出现 55 次。
   ⇒ **需确认 A3 走哪个分支**（若走 arch35，这两项是死代码）。

### 4.2 `HcPre` kernel 结构（若决定攻它）

* `csrc/moe/hc_pre/`（**源码完整可用**，含 op_host/op_kernel，4082 行）
* 结构：`KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_MIX_AIC_1_2)` + **两段**（Part1 写 workspace → Part2 读）
* 同步：`hc_pre_m_k_split_core_arch35.h` 11 处、`hc_pre_m_split_core_arch35.h` 13 处
* **内层 K 循环每轮 2 次 cross-core 同步**（AIC 等 AIV 写完、AIV 等 AIC 算完）
* **我们的 K 很小 ⇒ 循环退化为 1 轮 ⇒ AIC/AIV 无流水深度，严格串行**

## 5. 已封闭路线（**不要重复投入**）

| 路线 | 判定 | 关键证据 |
|---|---|---|
| 跨层软件流水（层 L 的 AIV ‖ L−1 的 AIC） | ❌ 无合法调度 | 层 L+1 第①个算子吃层 L 的**最后一个**算子输出 |
| 跨 micro-batch（ubatching） | ❌ 代价 ×1.7 | 图内串行 vs 并发曲线**完全重合** |
| 跨请求并行 | ❌ 不存在 | 同一 batch/同一图/同一条流 |
| 通信与计算重叠 | ❌ 结构性 | `COMM ∩ AIC = 0.000`；消费者立即依赖 |
| MoE 带宽 | ❌ 已峰值（1292 GB/s） | 微基准 g=48 |
| `HcPre` × `limit_core_num` | ❌ 核数无关 | AIC 24→4，设备时长恒定 34.0~34.6 µs |
| `HcPre` 减 Sinkhorn 迭代 / 原生实现 | ❌ eps 卡死 / 慢 35× | `HCPRE-AND-SCATTER-DEEP-DIVE` |
| `hc_pre_norm` 融合 | ❌ 无可测收益（0.34%<下限） | 5 臂 A/B |
| gmm1 kernel 变体 | ❌ armC 崩 / armD 无效 / **OPT-A+OPT-F 已在交付 armF 里** | diff 证明 `OPT-F` = armF 本身 |
| 注意力矩阵乘"换算子" | ❌ 不是算力受限 | `MatMulV2[6,4096;4096,1024]` = 23.84 µs vs 计算 0.17 µs（**140×**） |
| F1/F2 融合 | ❌ 尾链只超出主流 0.128 ms | `prof_tail_critical` |
| F3（`npu_rms_norm_dynamic_quant`） | ❌ **算子签名挡住** | 只吐 int8+scale（**无浮点 y**，indexer 需要）；且与参考不逐位相等 |
