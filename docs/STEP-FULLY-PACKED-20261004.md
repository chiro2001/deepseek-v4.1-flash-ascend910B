## 3. ★ 一个测量口径的澄清：bench 的 N=1 tok/s 是**调和平均**

用单 prompt 直测（`step_tail.py`，1024 tokens，240 chunks）：

| 量 | 值 |
|---|---:|
| 步间隔 中位 / 均值 | **25.50 / 25.59 ms** |
| p10 / p90 / p99 / max | 25.10 / 25.78 / 26.64 / 51.35 ms |
| 该请求的 A | **3.267** |
| **实测 tok/s** | **123.7** |

而 `bench_concurrency` 在同一实例上报的 N=1 是 **107.6**（A=3.48）。

**为什么差 15%**：bench 的 `--concurrency 1` 会把**全部 16 条 prompt 依次跑完**，
`total_decode = Σn_out / Σwindow`，而 `window_i ∝ 1/A_i` ⇒
**上报的 tok/s 是各 prompt 接受长度的调和平均 ÷ 步长**，而 `/metrics` 的 A 是 token 加权平均。
16 条 prompt 的 A 相差很大（实测从 1.51 到 4.8），调和平均被低 A 拉低。

⇒ **这不是服务问题**，但**报数时必须注明**：`tok/s` 依赖该档所用 prompt 样本的 A 分布。
同一 prompt 集内的 A/B 对比仍然有效（本轮所有 A/B 都满足这一条）。
