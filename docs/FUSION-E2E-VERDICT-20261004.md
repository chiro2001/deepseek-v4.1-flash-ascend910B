## 2. 判读：**没有一个一致的单变量效应**

| N | B 相对两条 A 臂 | 是否支持"融合更好" |
|---:|---|---|
| 1 | 26.8 vs 26.2 / 26.2 | ❌ 略**差** |
| 2 | 36.2 vs 35.7 / 34.5 | ❌ 略**差** |
| 4 | 49.1 vs 49.2 / 51.5 | ➖ 打平（且 A2 更差，说明是噪声） |
| **8** | **67.0 vs 71.2 / 73.2** | ✅ **好 6–8%** |
| **16** | 102.9 vs 106.3 / **100.0** | ❌ **A2 更好** |

**⇒ N=8 看起来赚了 6–8%，但 N=16 是反的** ⇒ **不能归因于融合**，
而是**本机 run-to-run 的 ms/step 离散（1–4.4%）覆盖了融合的理论收益**。

### 2.1 与理论预期对照

算子级实测（die5，M=96，20 次 profile 中位）：attn 省 **11.75 µs**×43 + FFN 省 **2.67 µs**×43
= **0.62 ms/step**。而本轮 ms/step 的噪声量级是 **0.3–3.2 ms**（按各档 1–4.4% 算）——
**理论与噪声同量级** ⇒ 单次 A/B 不可能判定。

### 2.2 正确性（臂 B）

| 用例 | 结果 |
|---|---|
| `regress2.py`（17×23 / count 2000+16000 / needle 904+8000） | **5/6 PASS** |
| 并发一致性（8 路 vs 单流） | **6/8**，差异仅空白（已知项） |

⇒ 融合版**功能正确**，只是性能收益测不出来。

## 3. ★ 途中踩到的坑（两处，都留档）

### 3.1 `V41_DCP_MOUNT` 会**覆盖** `patches/files/model.py`

`serve_a2.sh` 的挂载顺序是"DCP overlay **最后**追加"⇒
设了 `V41_DCP_MOUNT=$HOME/dcpw` 时，`~/dcpw/vllm_ascend/models/deepseek_v41/model.py`
会**盖掉**我们刚打补丁的 `patches/files/model.py`。
**症状**：容器里 `grep -c V41-HC-FUSE model.py` = **0**（看起来"补丁没生效"）。

### 3.2 编译缓存不以 env 为 key ⇒ 翻开关必须同时换文件

第一次做 A 臂（同一个 model.py，只把 `V41_HC_FUSE_NORM` 从 1 改回 0）时，
vLLM 命中了**臂 B 的编译产物**，启动即报：

```
AttributeError: '_OpNamespace' 'dsv41_ops' object has no attribute 'hc_pre_norm'
```

⇒ **A/B 两臂必须用内容不同（或逐字节相同于历史）的 model.py，或清 `~/.cache/vllm`**。
本轮最终用的是"融合前的备份文件"，正好命中历史缓存，启动最快。

### 3.3 顺带给 `serve_a2.sh` 加了四个 env 透传

`V41_HC_FUSE_NORM` / `V41_HC_FUSE_ATTN_FP32` / `V41_HC_NORM_LIB` / `ASCEND_CUSTOM_OPP_PATH`
（原来不在白名单里 ⇒ 传了也进不去容器）。
⚠️ 注意：**注释不能写在 `docker run` 的续行参数之间** ——
`\` 续行后紧跟 `#` 会让后续行变成**新命令**（实测报 `-e: command not found`）。

## 4. 建议

| 选项 | 说明 |
|---|---|
| **保持 `V41_HC_FUSE_NORM=0`（默认）** | 本轮**没有测到收益**，按纪律不该转正 |
| 若要继续验证 | 需要**同会话内交替 A/B**（或把噪声压到 <1%），否则 0.62 ms/step 永远测不出来 |
| 融合算子的真正价值 | 它是**设备工作量**的削减（12.4% 的 HcPre 独占里的一部分），在**噪声更小的平台/更长序列**上更可能显现 |

**诚实结论：融合算子功能正确、算子级收益已确证（−0.62 ms/step 上限），
但在本机 TP8 上端到端效果被 1–4.4% 的 run-to-run 离散掩盖，本轮无法判定。**
