## 3. ★★ 【实测】`ENGRAM_TUNE` 的两条判死 + 一条目标级结论

### 3.1 嫌疑 A（gate 的 64× padding 冗余）**判死**
代码痕迹：`serve_a2.sh:1015` 无条件挂 `engram_gate.py`（md5 `146010ca`），其 `:201` 是
`if chunk <= 0: return _engram_gate_reference(...)`；**全仓 48 条臂零例外都打 `GATE_CHUNK=0`** ⇒ **走 stock 参考实现**，
`V41_ENGRAM_GATE_MAX_TOKENS` **一个字节都不被读**。
★ 更关键的更正：**decode 图的 token 维是 6 不是 2048/8192** ——
`cudagraph_capture_sizes=[1,2,3,4,6,8,...,192]` + `FULL_DECODE_ONLY`，单流 n=6 **且 6 就是 capture 桶**；
臂日志 448 行 decode **全是 `n=6 padded=6`**；`_engram_max_tokens=8192` 只决定 persistent buffer 形状。
⇒ **历史那 6.48 GFLOP / 8.55 GiB 已经是 0，`roundup_n` 不必再碰。**

### 3.2 嫌疑 B（`H_after` ≈ 8–15 ms）**判死**
c2 同形循环（`pipeline_law.py`，D 校准 29.647 ms）：
- **b 扫描**：b=0/1.6/5/10 → hp = 29.699/31.426/34.750/39.738 ⇒ **斜率 1.004**、截距 ≈ D。
- **s 扫描（关键）**：s=0…24 → hp **完全平（31.12–31.44）**；s=28/32/40 → 35.12/38.43/46.73
  ⇒ **拐点 = D−a**，**负对照成立**（尺子有判别力）。
⇒ 恒等式 **`hp = G + b + ε`**：**只有 b 与 G 计费**；`hp − total`（本臂 s≈14.6 ms）**在 `s < G−a` 时 100% 免费**
（本臂余量还有 ~10 ms）⇒ **我此前把 `hp − total = 16.5 ms` 当成"H_after 是最大单块"是错的**（那是最大的**空转**块）。
⇒ 真正的 `H_after = b+ε ≈ 1.6–1.9 ms`。

### 3.3 ★★★ 目标级结论：**步是设备限定的**，`≤24` 必须从**非 Engram 的设备工作量**里挖
| 项 | 值 |
|---|---|
| `G`（设备每步图执行） | **≈29.5 ms（tierB）/ ≈30.6 ms（merged）** = 整步的 **93–95%** |
| Engram 在关键路径上的**全部盘子** | **≈2.3 ms**（route 1.40 + gate 0.321 + wkv ≤0.279 + pad ≤0.20 + hash 0.088） |
| ⇒ **把 Engram 全删干净** | 31.1→**≈28.8**、32.2→**≈29.9** ⇒ **仍到不了 24** |

★ **int8 残余的归属**：Δhp = 32.223 − 31.114 = **+1.109**，而两档 `b` 逐字相同（1.634 vs 1.614）
⇒ **int8 残余 100% 落在 `G`**，与 Engram 侧 1:1 叠加。

### 3.4 gate 的真实成本（**差点判错 4 倍**）
- eager 口径 2 层：n=1/6/32/192 → 1.085/1.096/1.103/1.115 ms ⇒ **与行数无关**（纯"算子个数×固定成本"）。
- ★ **ACL 图重放口径**（`NPUGraph` 捕获后 replay）：n=6 → **0.321 ms**、n=192 → 0.556 ⇒ **eager/graph = 3.68 / 2.14**。
- 生产里 gate 在 `npugraph_ex` 图**内部** ⇒ **要用 0.321，不是 1.27**。
- 顺带量到 `CHUNK=0` 白拿了多少：同形状 `CHUNK=512,MAX=2048 → 5.62 ms`、`MAX=8192 → 21.97 ms`（eager 口径）。
