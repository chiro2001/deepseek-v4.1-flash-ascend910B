# 用**实际量化权重**做层对比：走到哪一步、卡在哪

> 2026-09-21 23:5x。用户澄清：要用 A3-node1 上**我们实际导出的量化权重**，
> 而不是"把官方权重重新量化"的代理。以下是按这个要求做到的结果 ——
> **有实质进展，但没走完，卡点讲清楚**。

---

## 一、做到了什么

### 1.1 两边的格式都解开了（【实测】）

| | 官方 | 我们 |
|---|---|---|
| `layers.0.ffn.experts.0.w1.weight` | **I8 [2304, 2560]** + `scale` **F8_E8M0 [2304, 160]** ⇒ MXFP4，E2M1 + **block 32** | **I8 [1152, 5120]** = `[N/2, K]`，`weight_scale` **F32 [2304, 1]** |
| 量化粒度 | 每行 **160** 个 scale | 每行 **1** 个（per-channel） |
| offset | — | **全 0**（对称成立，已实测） |

⇒ 我们的解码器（nibble → int4 → ×scale）**数值上能解出合理分布**：std 0.00281 vs 官方 0.02188。

### 1.2 ★ 一个独立证据：w2 的输入侧变换是**满秩**的

我对三张矩阵做了"逐块线性映射"拟合（求 X 使 `W_official · X ≈ W_ours`，块越大拟合越好）：

| 矩阵 | 形状 | K 侧块 1 | 块 32 | 块 256 | 块 512 |
|---|---|---:|---:|---:|---:|
| **w1** | [2304, 5120] | ~0.115 | ~0.111 | 0.1056 | 0.0987 |
| **w3** | [2304, 5120] | ~0.12 | ~0.121 | — | — |
| **w2** | [5120, 2304] | **0.9999** | **0.9968** | **0.9747** | — |

**读法**：
* **w1/w3** 的输入侧（K=5120，即 hidden）**近似块对角** ⇒ 主要是一个**对角缩放**（就是配方里的 `flex_smooth_quant`），残差 **11–12%**；
* ★ **w2** 的输入侧（K=2304，即 **FFN 中间维**）**任何块大小都拟合不出来**（连块 1 = 纯对角都失败，残差 0.9999）⇒ **那里是真·满秩旋转**。

⇒ **这独立印证了 QuaRot 的结构**：MLP 的旋转恰好插在 gate/up 与 down 之间、
作用于**中间维**，所以只有 w2 的输入侧带满秩旋转。**这个结论不依赖任何假设**，
是从数据里量出来的。

## 二、卡在哪：**旋转是嵌套的，不能孤立反解一个矩阵**

我试了三条路，都失败：

### 2.1 逐块正交 Procrustes（假设 `W_ours = W_off @ R`，R 块 32 正交）

```
w1  残差中位 6.80     w2  2.02     w3  3.27
```
残差 **大于 1**（比"直接预测 0"还差）⇒ **假设不成立**，
变换里除旋转还有对角缩放（smooth/AWQ）。

### 2.2 放宽成"块内任意线性"

```
w1  0.1114 ✔      w3  0.1216 ✔      w2  0.9968 ✘
```
w1/w3 通了（对应 §1.2 的结论），**w2 仍不通**（因为它是满秩，块内解不出来）。

### 2.3 ★ 直接跑层前向（把拟合出的"有效权重"代进去）

```
gate Δ=1.0067   up Δ=1.0238   中段 Δ=0.9975   ★ FFN 输出 Δ=1.0001  cosine=-0.0044
```

**Δ≈1.0、cosine≈0 ⇒ 输出与官方完全无关。**

**根因**（这一步是这次最有价值的认识）：
QuaRot 的旋转**不是只作用在一张矩阵上**，而是**每隔几层插一次、前后配对**：

```
y = (x·R) · (W·R)ᵀ        ← 单看这一层，函数确实不变
但下一层的输入是 (y·R')，而 R' 与 R 是配对的
```

⇒ **单独把 w1/w3 反旋回官方基，再拿未旋转的 x 去算，等于把配对关系拆了。**
所以逐矩阵反解**在原理上就不成立**，不管拟合多准。

## 三、要用实际权重做层对比，正确的做法只有两条

### 路线 A（推荐）：**从 msmodelslim 拿旋转图谱，重放整条链**

旋转是**确定性生成**的（`msmodelslim/processor/quarot/common/hadamard.py` 里
有一张 Hadamard 表：`had.200/172/160/156/140/136/108/76/60/52/36/28/40/20/12`），
并由 `QuaRotInterface.get_rotate_map(block_size)` + `RotatePair` 描述"哪两张矩阵配对"。

**步骤**：
1. 在本机 msmodelslim 里跑 `get_rotate_map(32)`，拿到 **RotatePair 列表**（纯 CPU，不需要 NPU）；
2. 按 pair 重建 R（Hadamard 或 `had.*.txt`）；
3. 对某一层，把 `x` 按上游 R 转过、用**我们的实际权重**算、再按输出的 R 转回来；
4. 与官方的 `x · Wᵀ` 比。

**成本**：半天。**收益**：能对**任意层、任意专家**给出真实的逐层输出偏差。

### 路线 B（更省事、更贴生产）：**W4A8 vs W8A8 直接对跑**

A3 上已经有 `~/models/DeepSeek-V4.1-Flash-w8a8-metadata`，
而发布脚本能产出 W8A8 权重。**同一输入、同一层、两个 checkpoint 对跑**，
差异就是"int4 相对 int8 的净代价"—— **完全不需要知道旋转**，
因为两边是同一套预处理、同一个基。

**成本**：要重跑一次量化 + 起两次服务；**收益**：直接给"4-bit 值不值"的答案，
而且是端到端口径（可挂到 GSM8K / 逐层 hook）。

## 五、结论

1. **"用实际权重做逐层对比"是可行的，但不能靠反解单张矩阵** —— 旋转是配对的；
2. **本次拿到两个硬结论**：① 格式与粒度已完全解码（我们 per-channel vs 官方 block-32）；
   ② **w2 的输入侧是满秩旋转**，独立印证了 QuaRot 插在 MLP 中间维；
3. **下一步二选一**：路线 A（重放旋转图谱，半天）或路线 B（W4A8 vs W8A8 对跑）。
   **我建议先做 B** —— 它不需要碰旋转，直接回答"int4 值不值"，而且能顺手做成端到端口径。
