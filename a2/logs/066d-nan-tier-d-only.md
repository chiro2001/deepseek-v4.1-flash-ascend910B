## 2. ★★ 判决：NaN 是档 D 独有（`out13`）

| 臂 | 档 | `same` | ★含 nan 的 400 | `parseErr`（流式跳块） | mismatched |

| `c2-nan-B` | **B** | 8/8 | **0** | **0** | — |

⇒ **NaN 是「请求相关 + 确定性」的**，**不依赖是否命中缓存**。

### 2.1 ⛔ 我否证了自己的伪影假说

`066c` 之后我提出：「文本变短可能是 NaN 让 SSE 块的 JSON 非法 ⇒ 我的客户端
`except JSONDecodeError: continue` 静默跳过 ⇒ 看起来变短」。为验证它，我给那个 `except`
**配了计数器 `n_parse_err`**：

```
三档 parseErr_fill / parseErr_replay = 0 / 0
```

⇒ ★ **假说被否证**：**流式块的 JSON 完全合法、没有 NaN**。
⇒ **066b/066c 的「输出变短 / 内容改变」结论成立、不需要撤回**；
   而 NaN 只在 **非流式 + `logprobs`** 这条路径上出现 ⇒ **两个现象、两条独立链、都只在档 D**。

★ 这条判据的价值不在「证实」，而在**排除了一个错误解释** —— **否决也是结论**。

## 3. NaN 的位置特征：外部客户端拿不到（诚实边界）

主代理要求给出「NaN 是整条 hidden 还是个别元素」。**做不到**，原因：

```
客户端能看到 NaN 的唯一位置 = 服务端的响应体（序列化 logprob 时炸）
• 流式：块里没有 NaN（parseErr=0）
• 非流式：整条响应 400，看不到任何张量
⇒ 从「外部」这一侧拿不到 NaN 的分布。
```

★ 但有一条**可用的替代信息**：NaN 在**同一请求的 fill/replay 两轮都出现、失败集完全相同**
⇒ **请求相关且确定性** ⇒ 与 `045`「整条 hidden NaN」的方向一致
（个别 logit 溢出通常不会整条请求稳定重现）—— ⚠️ 这是【推断】，不是读数。

### 3.1 最小方案（下一轮，约 4 min，只占 c2）

在 `_native_attention` 出口与 final logits 前各加一处**只读**检查（`C2_NAN_PROBE=1` 门控）：

```
n_nan      = isnan(hidden).sum()
n_rows_bad = isnan(hidden).any(-1).sum()
同时看 isinf（045 那轮 fp16 是先 inf 再 NaN）
```

判读：`n_rows_bad ≈ 全部行` ⇒ **整条 NaN**（045 同款 ⇒ 指向同一条读路径）；
`n_nan` 少而 `n_rows_bad` 多 ⇒ 稀疏 NaN；**首个出现 NaN 的层** = 病灶层。
★ 我倾向先查 `_kv8_cmp_plane` / `kv8_ori_plane` 的**反量化**在 `scale==0` 或 `payload==-128` 时是否产出 NaN。

## 4. ★★ 三条硬规律（用已有数据挖出来的，不需要再改代码）

用 Python 直接读 `out8`/`out9` 的 `textprobe.json` 得到：

| 规律 | 实测 |
|---|---|
| **① 坏臂的 replay 文本永远是 fill 文本的前缀** | 全部异常条目 `fill.startswith(replay) == True`（无例外） |
| **② `n_sse_pieces` 从 9 → 2–3，而 `finish_reason` 仍全是 `length`** | 即**用满 16 token 但非空文本块数骤减** |
| **③ 异常集跨臂/跨档完全一致** | `len512`、`len1024`、`out9/c2-tpf-512` 三组独立数据给出**同一批 prompt** |

★ 三条合起来说明：**不是「模型算得不一样」，而是「流式路径上某些块不再产出非空文本」**
—— 具体原因（空串 token？被 `skip_special_tokens` 吃掉？块本身丢失？）**仍未确认**，
但它**与 NaN 无关**（parseErr=0），是**独立的一条链**。
