| 臂 | 档 | 真有取回？ | `hp` | `d2h` | `total`（`prepare_engram` 内） | `hp − total` |
|---|---|:--:|---:|---:|---:|---:|
| `p2g-fix075` | int8 **OFF** | ✓ `CPU_to_GPU=2.1519269888e+10` | **30.260** | 10.039 | 12.770 | 17.49 |

### 1.1 但 `d2h` 是**温度计**，不是病（`D2H_advance` c2 实测，主代理逐行复核原始 JSON）

生产同形循环（设备 D → host `H_before` → `.cpu()` → host `H_after`）：

| D | H_before | H_after | **周期（= 步墙钟）** | **d2h** |
|---:|---:|---:|---:|---:|
| 32 | 4 | 4 | 35.757 | 26.564 |
| 32 | **0** | 4 | 35.755 | **30.557** |
| 32 | **8** | 4 | 35.847 | **22.584** |
| 32 | 4 | **0** | **31.810** | 26.599 |

两式逐点成立：**`周期 = D + H_after`**、**`d2h = D − H_before`**。
⇒ **挪动 D2H 的发出时刻只改 `d2h` 这个读数，一毫秒 wall 都不变。**
⇒ 据此解两档真实值：**tierB ⇒ D≈22.7 / H≈8.4；tierC ⇒ D≈71.8 / H≈8.6**
（`H` 不变、`ΔD ≈ +49.1 ms`）。
★ **`d2h` 是"调用瞬间仍在飞行的设备工作量"的 1:1 指示器**（两个独立装置双盲复现：
`T = 0.9693·W − 0.273`，R²=**0.99996**，饱和负对照到 W=256 ms 仍线性；空队列 0.024–0.030 ms；
反例臂"每 kernel 后 host 同步"⇒ W 涨 16× 而 T 恒 0.029–0.038 ms）。

## 3. ★★ 四个互相矛盾的读数（本卷的核心未决问题）

同一个量（"int8 读侧重建的每层成本"），四个装置给出**跨 200×** 的结果：

| # | 装置 | 口径 | 每层成本 | 换算 40 层/步 |
|---:|---|---|---:|---:|
| ① | `PROF_int8` **micro**（c0，合成张量，40 层入图） | 生产形状 B=1×6 行 | **129.1 µs** | **5.17 ms**（读）+0.39（写）= **5.55** |
| ② | `023`/`026`（历史，40 层整图，B=8，紧凑页） | 整层 A/B | **+139.5 µs** | 5.58 → 融合后 0.51 |
| ③ | `D2H_advance`（c2，40 层整图，**生产页步长 476416**） | 前缀法 | **682.8 µs** | **27.3** |
| ④ | `BF16_AB`（c1，**单卡真 forward** profiler） | `aclnnIndexSelect_Slice` 1672 µs × 74/步 | — | **≈124 ms** |

### 3.1 ③ 与 ② 的差已定位到**页布局**（`D2H_advance` 实验，主代理复核）

同一 rebuild，只改 `stride(0)`：

| int8 面页步长 | 图内 rebuild | 其中 `gather_i8` |
|---:|---:|---:|
| **476416**（宽=8192 时） | 682.8 µs/层 | **450.0** |
| **65536（紧凑）** | 230.9 | **7.4** |

⇒ **023/026 的 harness 用 `allocate_views` 建面 = 紧凑格**，所以他们测到 128.5–139.5 µs/层；
而生产的 SWA 面是**混合槽页上的 `view()`**（`core/deepseek_v41.py:374-381`，`stride=(block_stride//itemsize,…)`）
⇒ `index_select` 退化成"24 段各 64 KB、相距 476 KB 的散拷贝"，等效带宽 **3.4 GB/s**。

### 3.2 ★ 但 476416 **不是档 C 的步长**（`SWA_COMPACT` 复核 + 主代理核对 020 表）

| 组合（long-KV / SWA） | `pool_bytes_per_block` | slot 页 |
|---|---:|---|
| bf16 / bf16（**档 B**） | 540928 | `[131072, 131072, 131072, 147712]` |
| **bf16 / int8（档 C，= 在跑的）** | **540928** | **`[131072, 131072, 131072, 147712]`** |
| int8 / int8（**档 D**） | 476416 | `[131072, 131072, 131072, 83200]` |

⇒ **476416 是档 D 的 Σ**。档 C 的真槽页是 **131072（slots 0–2）/ 147712（slot 3）**
⇒ `SWA_COMPACT` 正在测 `--strides 131072,66560,147712`，**判读**：若 `gather_i8` 掉到 ~50 µs 量级
⇒ ③ 的 27.3 ms 是**非生产步长造成的假象**，与 ① 一致；若仍 ~440 µs ⇒ 跨步视图确实是病根。

### 3.3 ④ 与 ① 的 200× 待解释（`BF16_AB` 正在给分位数）

④ 是**单卡真 forward**（TP=1 ⇒ per-rank KV 张量比 TP=8 大 8×），且 profiler 窗口可能含多请求
⇒ **不能直接外推**。已让 `BF16_AB` 报该算子的 `min/p50/p90/max` 分箱 + 输入 shape/stride，
以判"1672 µs 是真值还是被少数极值/相位污染拉高的 avg"。

## 4. 【实测】档 C 的 SWA int8 **在 HBM 容量上是 ×1.000**

`020 §2` 的逐项对账 + 8 卡实测**双向吻合**：
- 档 B 与档 C 的 `GPU KV cache size` **都是 427,643**（主代理核过五条臂：`tierB`/`exact`/`mode2`/`fit`/`final` 逐字相同）；
- 档 D 才是 **485,610**（= 427,643 × 1.135 ✓）。

原因：slots 0–2 被 `compressor_state` 的 **FP32 state ring 131072 B** 顶住 ⇒ SWA 从 131072 砍到 66560 **白砍**。
⇒ 【推断·强】**若 SWA int8 同时还是那 49 ms 的大头，则它在 HBM 上是纯亏本**。

★ **但"24% 宿主 DRAM 节省（`092` 的 ×0.7607）归谁"仍未分离**：
主代理曾用 `Σpage` 推算"逐位吻合 0.7604"，**该算术已撤回**（分母 1094272 是推算值，不是实测值）。
真实实测：`tierB`（2 分量）`Σpage=910208` / 宿主 9.374 GiB vs `mode2`（**真分量**）`Σpage=832128` / 宿主 7.130 GiB
⇒ 比值 **0.9142 ≠ 0.7607**。⇒ `092` 的 24% 是在**同分量**的 tierB/mode2 上测的，**必然由 int8 引起**，
但**"SWA int8 还是 ring16"未分离** ⇒ 交给 §5 的阶梯臂 + `BF16_AB` 的张量字节对照。

## 6. 融合 kernel：**在多行/生产形状上是可行的**，但收益只占 ~9%

`FUSE_MULTIROW` 已交付（**纯 CPU、离线验证 exit=0**）：
- 结论：**可行**。两道 guard 只是"纯 decode 形状"的省略判据，不是语义边界；
  "多行"在 SWA 面的表达 = 栅格改 2-D `(num_reqs, PP×(BS//ROWS))` + `PP` 由 host 上界算（生产 = **3**）；
  cmp 面需 host 预计算 `(q//reps)*width` 偏移（kernel 内不能有非幂次 `//`）。
- 产物：合并件 `dsa_multirow_merged.py` md5 **`27547a70cc276eb5c1109dc57aec9e34`**；
  kernel `kv8_fuse_triton.py` md5 **`8057b3eb36622ee419d9a8c81d3ff73b`**。
- 离线判据：**17 例分派矩阵**（生产形状读出 `PP=3 / USE_QLEN=True / grid=(1,192)`）、
  `rows_bound`/`graph_safe` **原样转发**、`KV8_PREFILL` 段保留、行映射逐元素等价、`py_compile` 过。
- ★ **负对照**：未推广的原版在生产形状下**回退时丢 `rows_bound`/`graph_safe`** ⇒ 原样上车 = **收益 0 + `EE1016`**。
- 收益预测（生产口径，**分项算术外推**）：**≈4.4 ms/step（区间 2.4–5.6）** ⇒ 占 49.3 的 **~9%**。
- ★ **接线缺口**（`CENSUS_int8` 查证）：`shadow-pkg/scripts/serve_a2.sh:948-952` 的挂载**不含**
  `kv8_fuse_triton.py` ⇒ 它现在**只来自镜像**（容器重建即丢）⇒ 已让 `FUSE_MULTIROW` 出接线补丁 + 前置指纹门。
