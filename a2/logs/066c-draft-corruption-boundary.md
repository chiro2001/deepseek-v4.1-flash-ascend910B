## 1. ★ 触发边界（`out8`，判据 = `text_probe.py` 的 fill/replay/replay2）

| prompt | `same` | `det`(replay==replay2) | `max_shrink` | mismatched |
|---:|---:|---:|---:|---|
| 128 | 8/8 | 8/8 | 0 | — |
| 256 | 8/8 | 8/8 | 0 | — |
| **512** | **5/8** | **6/8** | **85** | **[4, 5, 7]** |
| **1024** | **4/8** | 8/8 | **98** | **[1, 2, 4, 5]** |
| 2048 | 8/8 | 8/8 | 0 | — |
| 4096 | 8/8 | 8/8 | 0 | — |

逐条字符数 `(fill, replay, replay2)`：
```
len512 : [(48,48,10), (48,48,48), (40,40,40), (152,152,19), (88,21,21), (112,27,27), (144,144,144), (104,24,24)]
len1024: [(64,64,64), (72, 9, 9), (104,13,13),  (40,40,40),   (80,10,10), (112,14,14), (10,10,10), (8,8,8)]
```
★ **`len512` 的 p0/p3 又是"首轮 replay 正常、第二轮才变"**（`48→48→10`、`152→152→19`）
—— 与 `out7` **同一位置** ⇒ 066b §2.3 的"**进程内累积**"从 1 次观测升为 **2 次独立观测**。

### 1.1 ⚠️ 两条必须一起读的限定

1. **统计功效**：每档只有 8 条 prompt。`512` 是 3/8 ≈ 0.38。若真实复现率恒为 0.38，
   单档 8 条全清的概率 ≈ 2.1%；**四档同时全清** ≈ 2e-7 ⇒ **边界大概率是真的，但仍是概率论证**。
2. ★★ **非单调 ⇒ 不可外推**（本卷最重要的一条）：
   `4096` 比 `512` 长却干净、`128` 比 `512` 短也干净 ⇒ **边界函数未知** ⇒
   **不能**用"2048/4096 干净"推出"131072 干净"，**也就不能**用它给 8 卡臂定触发条件。

### 1.2 顺手排掉的三个几何假设

```
tiny-draft config： sliding_window = 128 ；blocks_per_chunk(default) = 8 ⇒ tokens_per_chunk = 1024
★ 512/1024 这个窗口 既 ≠ 滑动窗口(128) 也 ≠ chunk 边界(1024)
  （128/256 同样 <1 chunk 却干净；1024 恰好 =1 chunk 而 2048 =2 chunks 却干净）
⇒ 不是这三个几何量中的任何一个。【未确认】
```

## 4. ★★ 代码级线索（未证实为根因）：**`kv8_ori_plane` 有两套实现**，而档 D 换的是**另一套**

为了看 prefill 的中间量，我先给**模块级** `kv8_ori_plane`（`dsa_v41.py:505`）插了 trace。
结果：
```
ori_plane/PREFILL        = 0 行      ← ★ 一次都没触发
cmp_plane/PREFILL-FALLBACK = 0 行    ← ★ 一次都没触发
ori_plane/BOUND          = 720 行（全是 decode 形状：num_reqs=6..8, rows_bound=6, pages_per_req=3, width=64, block_size=128, window=128）
cmp_legacy_triton        = 0 行      （这条 trace 是**发布件里本来就有**的）
```
**为什么是 0**：`grep -n "def kv8_ori_plane"` 给出**两个**定义 ——
```
505 :  def kv8_ori_plane(          ← 模块级（我插了 trace 的那个）
1656:      def kv8_ori_plane(      ← 缩进的、在 `if _kv8_prefill_enabled():` 里
```
★★★ **`dsa_v41.py:1653` 起有一段只在 `_kv8_prefill_enabled()`（即 `VLLM_V41_KV8_PREFILL=1`，
也就是【仅档 D】）时才执行的 import-time 代码，它把模块级的 `kv8_ori_plane` 整个换成
一个走 Triton 融合 kernel（`fused_ori_plane2`）的版本，并把
`DeepseekV41EagerAttentionImpl._kv8_cmp_plane` 换成 `_kv8_cmp_plane_prefill`。**
⇒ **档 D 的 prefill 走的是那套 Triton 实现，我第一版 trace 插在了"没人调用的那一套"上。**

### 4.1 ★ 这条线索里最可疑的一处（**未证实**）

```python
_kv8_model_meta = {"max_cache_seq_len": 0}          # ★ 模块级可变字典

def _native_attention_prefill(self, attn, q, metadata, **kwargs):
    attn_md = getattr(metadata, "attention", None)
    mcs = getattr(attn_md, "max_cache_seq_len", 0) if attn_md is not None else 0
    _kv8_model_meta["max_cache_seq_len"] = int(mcs or 0)      # ← 写
    return _kv8_native_attention(self, attn, q, metadata, **kwargs)

def _kv8_cmp_plane_prefill(self, ...):
    ...
    mcs = _kv8_model_meta["max_cache_seq_len"]                # ← 读（跨层、跨请求共享）
    ppr = max(1, -(-mcs // block_size)) if mcs else None
    return _kv8_pf_cmp(self, ..., ppr=ppr)
```
★ **三个可疑点**（都**没有**被证实）：
1. **`_kv8_model_meta` 是模块级全局** ⇒ 它由 `_native_attention`（每层都调）写、
   由 `_kv8_cmp_plane` 读 ⇒ **同一次 forward 里谁先谁后、跨请求是否残留**，决定了 `ppr` 是不是**上一个值**；
2. **`ppr` 是由"值"（`mcs`）算出来的页数**，而这个文件的**自己**的注释（另一处，
   `_kv8_cmp_plane_prefill` 里的 graph_safe 分支）明确警告过这个量：
   *"the Triton prefill kernel below sizes its scratch from `max_cache_seq_len`, a **value** the capture
   dummy batch reports as **6** ⇒ never use it on a graph-replayed step"*
   ⇒ ★ 这与 `049` 修的正是**同一家族**（**用"值"而不是"形状/常量"定几何**）；
3. `mcs` 是 **token 长度**，而长-KV 平面是**压缩**的（`compress_ratio ∈ {1,2}`）⇒
   对 ratio=2 的层 `ppr` **多算 1 倍**（安全但浪费），对 ratio=1 的层才是精确值
   ⇒ **过配是安全的，所以这条本身不构成缺陷**（必须如实标注，不许当结论）。

⚠️ **必须强调**：`cmp_legacy_triton = 0` ⇒ 在**本轮这批臂**里 `_kv8_cmp_plane_prefill` 的
**非 fast-path 分支一次都没走到** ⇒ 上述 `mcs/ppr` 代码在本轮的 6 档里**可能根本没被执行**。
⇒ **这条是线索，不是根因。** 要证实它，下一步必须给 **`1653` 段那套实现**插 trace
（而不是我插错的 505 那套），并确认 trace 覆盖**真实压测流量**（本轮的 720 行 trace 全来自
warmup/capture 的 dummy run —— 这本身也是一个"**trace 覆盖率**"陷阱）。

## 6. 诚实边界

1. **边界只有 6 个采样点、每点 8 条 prompt** ⇒ 统计功效有限（§1.1）；
2. **机制未定**：分支相同、`topk` 相同，差异在数值里；§4.1 的 `mcs/ppr` 是**线索不是根因**；
3. **`cmp_legacy_triton = 0`** ⇒ 本轮没走到那条非 fast-path ⇒ 未覆盖；
4. **单卡 tiny + dummy 权重**：绝对 sha 不可外推；**"档 C 清白 / 档 D 有差异"这个二分是代码路径级的**（同 `063`），可传递；
5. **8 卡真权重未复现**（c0 被 ENGRAM 臂占着）⇒ ⚠️ 决定发布的最后一步仍未做；
6. `usage.completion_tokens` 仍未取到（066b §2.4 的遗留）。
