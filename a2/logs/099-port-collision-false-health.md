## 2. ★★ 根因：判据**没有绑定到唯一的对象**（本仓第 3 例）

`run_arm_r8.sh` 的起服判定是：
```
curl -s http://127.0.0.1:$PORT/health   → 200 就算"我的服务起来了"
```
而本仓所有臂都用 **`net=host` + 固定 `PORT=8050`** ⇒
**任何**在 8050 上监听的服务（哪怕是上一条臂的残留）都能满足它。

⇒ 与今天其它两条**同族**：

| 出处 | 判据被谁"冒充" |
|---|---|
| `079 §3` | 判据被**自己的提示文本**满足（字符串空间重叠） |
| `093` | 前置 env 没带全 ⇒ 跑的是**另一份文件** |
| ★ `099` | 判据被**另一个容器**的服务满足（端口空间重叠） |

共同的一句话：**判据必须绑定到唯一的对象**（唯一的文件 / 唯一的进程 / 唯一的容器 / 唯一的端口）。

## 3. ✅ 修法：新增 **G4 端口占用门**（已落 `run_4axis_arm.sh`）

起臂**前**断言端口空闲；被占就 `exit 64` 并打印处置命令：

```bash
G4_PORT_CHECK=${G4_PORT_CHECK:-1}
if ss -ltn | grep -qE "[:.]${PORT}[[:space:]]" || curl -sf -m3 "http://127.0.0.1:${PORT}/health"; then
    echo "⛔ [G4] 端口 $PORT 已被占用 —— 绝不能就这样起臂！" >&2
    echo "   （别的容器在同一个端口上服务时，起服判定会拿它的 200 当自己的 ⇒ 自检读空日志 ⇒ 误判 exit 9）" >&2
    echo "   ⇒ 先处理占用者，或换个端口： PORT=$((PORT+1)) bash $0" >&2
    exit 64
fi
```
