## 3. ⚠️ 这条负面结论的限定（不许当成"反量化安全"）

心跳行里**所有张量 `fmin=fmax=0.0`** ⇒ 它们**全是 0**。两种可能，**本轮没能区分**：

```
① `--load-format dummy` 下 KV cache 里本来就是零（或这批 prompt 没往这些平面写实数）
   ⇒ 那"无 NaN"是平凡的
② 我读到的缓冲是"死缓冲"（形状对、内容不是当步要用的那一份）
```
⇒ **正确表述**：**"这些张量上没有 NaN"** ≠ **"int8 反量化不会产 NaN"**。
★ 但**不改变主判决**：服务端确实返回了 400（NaN 是真的），只是它**不在这些张量上**。

## 4. ★★★ 我第三次踩了同一条坑 —— "探针实参的急求值"

| 次 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 第 1 次（066c） | trace 计数恒 0 | **同一个函数有两套实现**（模块级 vs import-time 替换） | 插到**真正被调用**的那一套 |
| 第 2 次（本卷） | 起服期 `EE1016=7` ×2 臂 | `int(isnan(x).sum())` 是 **D2H 同步**，捕获期致命 | helper 里加 `is_current_stream_capturing()` 守卫 |
| ★ **第 3 次（本卷）** | **加了守卫仍然 `EE1016=7`** | ★★ **`extra={...}` 是在【调用点】立即求值的** —— 守卫写在 helper 内部**拦不住**调用点上的 `(sel_scale == 0).sum()`（那也是 D2H 同步） | ★ **extras 改成 `lambda: {...}`（零参 callable），在守卫之后惰性求值** ⇒ `ee1016=0` |

### 4.1 ★★ 通用教训（建议进 `AGENTS §5b`）

> **"探针的惰性"必须覆盖到实参** —— 只把守卫放进被调函数是不够的。
> 任何在**调用点**求值的表达式（字典字面量、默认参数、`f(x.sum())`）都会**绕过守卫**。
> **判据**：凡是探针调用点的实参里出现 `.sum()` / `.min()` / `int()`，就要当成"**可能同步**"来审。

### 4.2 我把两条都做成了**生成器的 fail-closed 自检**（并反向验证过）

```
[gnan] 静态绑定自检通过（10 个调用点，全部在名字绑定之后）              ← 第 1 项（防"插在赋值之前"）
[gnan] 惰性自检通过（所有 extras 都是 lambda ⇒ 捕获期不会在调用点同步）  ← 第 2 项（防"实参急求值"）

★ 反向验证（把 extras 改回急切）：rc=5，报
   "2 个调用点的 extras 不是惰性 lambda ⇒ 捕获期会 D2H 同步 ⇒ EE1016"
★ 反向验证（把插入改回"之前"）：rc=1，报
   "`ori_plane/deq` 引用的 'deq' 在该调用点之前未绑定（插入方向错了）"

★★ 而且**第 1 项自检本身也有过一版假阴性**：第一版按 "(anchor 结束位置) 之前是否出现过 NAME ="
   判 —— 而锚点**自身就含** `deq = …` ⇒ 错误顺序下照样通过。
   ⇒ 改成对**结果源码**扫 `_c2_nan` 调用点，判据与真实运行时的名字解析**同序**，才真正有判别力。
```
