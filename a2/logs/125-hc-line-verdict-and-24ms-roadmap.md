## 2. 【实测】四个判决

### 2.1 Q1 **关闭**：sinkhorn 只值 0.31 ms/step，且**已经贴着硬件屏障地板**

| 项 | 预注册（`logs/120`） | **实测** | 判定 |
|---|---|---|---|
| 每轮成本 | 0.5–1.1 µs | **0.189 µs**（6 个独立读数 0.095–0.243） | **否决**（低 2.6–5.8×） |
| `20→1` 省 | 15–21 µs/次 | **3.59 µs/次**（6 个独立口径 1.81–4.62） | **否决**（小 5×） |
| 折算 | 1.29–1.81 ms/step | **0.31 ms/step** | **否决** |
| `iters=1` 落点 | 8–14 µs | —— | （见报告 §2.1） |

★ **机理（新，且很漂亮）**：profiler 显示 `iters=1` vs `20` 的 **AIC busy 几乎不变**（19.99 → 19.84 µs）、**AIV busy 只 +0.33 µs**（23.02 → 23.35），但**墙钟涨 2.98 µs**。
⇒ 那 3 µs **不是 pipe busy，是 38 个 `PipeBarrier<PIPE_V>` 的流水线排水**（≈79 ns/屏障）。
⇒ **这个循环已经贴着硬件的屏障地板**：4–16 个元素上的 6 个向量算子本身几乎不花时间，**能省的只有"少跑几轮"**。

### 2.2 §3 旁路 **被否**：iters **不能减**（它不收敛）

| 观察 | 值 |
|---|---|
| `y` / `post` / `pre` 在 `iters ∈ {1,2,3,5,10,20,40}` 上 | **逐比特相同（n_diff=0）** ⇒ 只有 `comb_frag` 随 iters 变 |
| `iters=3` vs `20` 的 `comb_frag` | **rel_l2 = 2.77e-2** |
| 传播到 `hc_post` 输出 | **2.42e-2** |
| `iters=20` vs `40` | **仍差 2.84e-3** ⇒ **没收敛** |
| 对 x 尺度的敏感度 | 对 **500×** 完全不敏感（真权重 + `hc_base` absmax 3.81 主导） |

⇒ ★ **"不动点已收敛 ⇒ 可以少跑几轮"这个前提本身不成立**。**这条路关闭**（且它本来就会动数值）。

### 2.3 Q2 **主成本 = Cube 阶段的 issue/scalar 开销**（逐项排除）

| 候选 | 实测 | 判定 |
|---|---|---|
| 权重带宽（`hc_fn` 1.87 MiB fp32 ×86/步 ≈ 160 MiB/步） | 热 vs **轮换 32 份**权重：**34.63 vs 34.79 µs = +0.16 µs** | ❌ **不是**带宽 |
| 算力 | AIC busy 19.84 µs 里 **MAC 只 1.28 µs（6.5%）**；**FLOP ×10.7 反而快 13%** | ❌ **不是**算力 |
| 发射 | 发射地板 **2.72 µs** | ❌ 只占零头 |
| **Cube 的 scalar** | **13.36 / 19.84 µs = 67%** | ✅ **就是它** |
| 其他 | K÷10 只省 19%、bf16 权重只省 8%、workspace ≤4.37 µs | ❌ 都不是 |

### 2.4 Q3 **只有写核才值**：现实 0.17–0.19，绝对上限 0.268 ms/step

* 同图相邻**完全可加**：`pair 40.68 = post 6.24 + pre 34.28`，**交互项 +0.159 µs/对**
  ⇒ **"把两个 op 一起调"（Python 层）零收益** —— 这直接**否决**了"抄 GLM5-next 的 `MHCFusedPostPreOp` 就能省"的设想（`logs/122 §5` 已指出 NPU 那份只是 Python 组合，本卷用实测坐实）。
* 融合能拿掉的只有 post 的任务开销 + 一次发射 ≈ **4.0–4.3 µs/对** ⇒ **0.17–0.19 ms/step**。
* "整个 post 消失"的**绝对上限** = 43 × 6.24 = **0.268 ms/step**。
* ⇒ ★ **`PROF_MINE §4.1` 排名 2 的 0.30–0.64 ms/step 作废**（它基于错单价 + "成对 = 一个 op"的假设）。
