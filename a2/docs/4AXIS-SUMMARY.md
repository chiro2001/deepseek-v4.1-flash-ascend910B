## 4. 我们是怎么达成的（方法论）

1. **一次只加一个轴，且必留反例臂** —— 每个轴先在单轴/单卡验通，再叠加；每一步都有 `=0` 的对照臂
   （如 `p1a(DG0)` 对 `p1b(DG1)`、`p2g(TRUE0)` 对 `p3b2(TRUE1)`）。
2. **一切都用"代码痕迹"复核**（md5 / 计数器 / 事件流），不看配置项的名字
   —— 这条抓出了 `085`（device-index 绕过整条 host 路径）、`093`（dsa 挂错份）、`081`（合并件过期）。
3. **把每次"看起来通过"都当成可疑** —— 今天的 9 次判据事故（自污染 / 跨相位 / 跨运行 sha / 端口冒充 /
   `pgrep` 自匹配 / 计数器同名不同义…）全部由此暴露，并各自沉淀成一道门或一条纪律。
4. **判决器不接受"缺证据 = 通过"** —— 未验项单列，避免"看不见所以全绿"。
